### Patterns
- [[circular-dependency-build-order]] — **Object A reads B, B reads A: a cycle cannot be scheduled, only broken — so whichever builds first reads a 24-hour-old copy of the other.** Any conservation identity spanning both sides is then silently wrong on its newest rows, on every build, while settled history looks perfect and all-time totals look reassuring. Proven on [[GP-322]] (ad-cost allocation reading 3.6x campaign spend). Carries the **detection recipe** (grep dimensions for self-reference; check both sides of every share read the *same* object) and two reusable techniques: **table vs live view** — one query, no theory, found the mechanism after three theory-driven reconstructions failed; and **zero-copy clone to pin a vintage** when daily `CREATE OR REPLACE` resets time travel to 0-day. Also: why **reordering the build is the wrong fix** (often impossible, and not provably a fixed point), why *"the logic is correct so SQL is the wrong layer"* is a trap (it is only *conditionally* correct), and why the affected window must be stated **age-relative, never as a calendar date** — two investigators independently misread an age gradient as an onset date and withdrew it.
- [[answerability-guard]] — **Making a model refuse questions it cannot answer** (2026-08-13). A star schema answers an unreachable slice by returning the **portfolio total against every member** — $2,858,931.54 against every brand, $128,757,189.40 against every campaign — and it is invisible to every ordinary check because the visual paints and the totals reconcile. Three verdicts (SPLITS / BLANK / ⛔ INERT), detected by asking whether the figure *splits across* the axis rather than what one member returns. Two operators, because each fails at the other's job: `ISCROSSFILTERED` for unreachable dimensions, `ISFILTERED` for unreachable facts that a valid axis crossfilters (naming those under ISCROSSFILTERED blanks every Date pivot). ⚠ Never guard control/mode tables, self-group columns, or measures on a fact that already has its own helper. Includes the four ways a guard test battery lies — comparing a value to itself, rebuilding cases from post-apply state (50 cases → 24, still ALL GREEN), vacuous passes, and no cross-fact cases. Applied to 4 facts across both Navira models.

- [[schema-dialect-drift]] — **A writer declares a column type in one vocabulary; the warehouse reports it back in another — so code comparing the two concludes "schema changed" on every write and forks a new versioned table each time.** One logical dataset spread across `TABLE_1 … TABLE_48`, each slice healthy in isolation. `_get_column_list` emits `bigint`/`datetime`; Snowflake reports `NUMBER`/`TIMESTAMP_NTZ`, so **any table with a `DATE` column forks unconditionally**. Bitten ALDC **three times in two repos** — [[prefect-connectors]] `6308783` (a 5-alias map missing the two spellings the writer actually emits; survived **11 weeks**), [[core_api]] Fix B ([[GP-277]], which chose the opposite *tolerate-and-widen* strategy), and again 2026-08-14 where a **real, measured** metadata-column mismatch was fixed and a virgin schema *still* produced 48 fragments. ⭐ **The lesson is not about types: a mismatch you can measure is not evidence that you found every mismatch** — a measured cause feels like *the* cause, and diagnosis-by-reading is how both competent attempts stalled. Carries the only test that settles it (**virgin-schema fragment count: 48 = broken, 1 = fixed**, and why re-using a dirty schema cannot distinguish the two), the sibling failure **a mutation test can itself be vacuous** (removing the folding left all 58 tests green), and a prevention checklist.
- [[three-layer-presence-census]] — **"Is X in production?" is three questions, and answering the wrong one produces a confident false negative about data we already pay to land** (2026-09-10, [[ALDC-1192]]). Measure **L1 deployed DDL** (`GET_DDL`, never the repo — the repo is a hypothesis about prod), **L2 modelled data** (`GROUP BY` the axis on the fact), **L3 raw landing** (`INFORMATION_SCHEMA.TABLES` name/`ROW_COUNT`/`LAST_ALTERED`) — they disagree routinely and each disagreement is a different finding. Asked whether Google/Meta were accidentally promoted to GEP prod alongside Sponsored Display, the three layers returned three verdicts: **Google/Meta genuinely absent** (zero objects, even raw), **nothing accidentally promoted** (deployed DDL matched the deploy branch exactly), and ⭐ **Sponsored Display arriving and invisible** — ~17,500 rows in prod raw, written to that same day, exposed via `DATA_SHARE`, and **selected by nothing**. Stopping at L1/L2 would have answered "we don't have Sponsored Display in production" — true, deeply misleading, and would have scoped a one-arm view change as a data-acquisition request. The mechanism is a hand-maintained fact whose branches are **named columns in a UNION**: upstream can start delivering a new category at any time, nothing fails, nothing alarms, the refresh stays green. Sibling of [[connector-field-addition-forks-the-table]] one layer up.
- [[vacuous-verification]] — **A verification pass can return a result that is structurally perfect and completely empty** (2026-08-14). Five defect claims were sent to independent verifier agents with a **structured output schema**; three came back `CONFIRMED` with `reasoning` literally the string `"test"` and evidence `"a"`/`"b"`, and one hit the schema retry cap and errored. The agents had genuinely done the work — **18–36 tool calls, 60–90k tokens each** — it was the *final structured emission* that degenerated. Re-running the same claims with a **free-text return** plus an explicit *"if you write the word 'test' here you have failed the task"* produced substantive verdicts including a programmatic byte-diff and an in-process repro. ⭐ **A schema-constrained agent return is not self-validating — check that the CONTENT of a verdict is substantive before trusting the verdict field**, and note that high token spend does *not* certify it (the spend was honest in every degenerate case). Collects the whole family: a green `claude / review` check (the bot ran, nothing was reviewed), a **vacuous mutation test** ([[schema-dialect-drift]]), a guard battery comparing a value to itself ([[answerability-guard]]), `trigger_and_wait` swallowing a sentinel exception ([[orchestrator]]), a **skipped** publish job that still reports a conclusion ([[github-actions]]), and a parity **coverage check that cannot fail** ([[prefect-connectors]] #25). **2026-08-27 adds a third shape — the INERT control, the most dangerous because it survives inspection**: a live `CORE_API_CLIENT_TOKEN` reached **9 tracked files / 10 pushed commits** over ~12 weeks while TWO correct controls existed — a `.gitignore` excluding `*.tmsl.json` (which **never affects already-tracked files**, so it landed and silently did nothing) and a redactor living in **1 of 13** scripts that serialize TMSL (the next rollback capture re-wrote the credential **two days later**, one file away). ⭐ **A fix that lives in a single call site is not a control; it is a coincidence re-enacted by memory.** Ask *how many call sites bypass it*, *does the rule apply to objects already in the state it forbids*, and *would it refuse or merely warn* — not *is the rule correct*. See [[pbi-xmla-automation]] for the operational half ([[GP-329]]). **2026-08-29 adds a fourth shape — a test that pins a weaker property than its own name.** [[agent-factory]]'s `evaluator.py` promises *"a verdict is accepted only if it names the evaluator identity, the bundle hash and the corpus"*, but `parse()` checked only that the keys **existed**, so `{'verdict':'PASS','promotable':True,'evaluator':None,'scored_against':None}` came back `is_pass=True, promotable=True`, summarised *"by unidentified, bundle ?"*, and `certify --remote` exited **0** — the factory's promotion gate. ⭐ The generalisable half is the test: `test_an_unattributed_verdict_is_not_believed` existed, passed, and **omitted the keys entirely**, pinning *presence* for a guarantee about *content*. Rewritten as 9 cases supplying null/empty/whitespace/wrong-typed values, **8 of 9 failed against the unfixed file**. **A test that supplies fewer fields than the failure mode needs is testing a different property than the one in its name** — construct the cheapest payload that satisfies the check and defeats the guarantee, and if it is not in the test, the test is not pinning the guarantee. ⚠ The counterpart trap: requiring every attribution field on every verdict would have broken the service's honest refusals, which null `scored_against` on purpose. **2026-08-29 adds a fifth shape — the verdict exists and the AGGREGATE discards it**, the inverse of the first four (content present and correct; the arithmetic one layer up throws it away). OpenSSF Scorecard `continue`s inconclusive checks out of **both** numerator and denominator, so **10 of 18 inconclusive still scores 10.0/10**; OHDSI computes `countPassed <- countTotal - countOverallFailed` so `notApplicable`/`isError` **round UP to passed**; XCCDF's ignore-list omits `ERROR`/`UNKNOWN` so they score **0.0, identical to FAIL**; Great Expectations computes `unsuccessful = evaluated - successful` with `successful = sum(exp.success or False)`, so a **crashed instrument counts as a failing expectation**; Grafana ships a **Set Normal state** handler for No-Data; pytest greens `skipped`/`xfailed` by default. ⭐ **The representation problem is solved everywhere; the aggregation problem is solved nowhere** — *a correct verdict is not a control until you have read what consumes it*; ask **if every check returned "could not measure", what does this system print?** Also carries the classic shape found inside a candidate: datacontract-cli's `create_checks.py` has **seven** `logger.warning(...) → return []` paths and **never imports `Run`**, so a declared rule that cannot compile vanishes and the run reports `passed`. ⚠ Instrument note: `gh api search/code` returned **0 for a string verified to exist** (no error) — **a zero without a positive control is NOT-VISIBLE, not ABSENT** — and `WebFetch` returns a *summary* even of raw source, so it is `DOCUMENTED`-tier; use `curl`/`gh api` for any claim carrying a verdict.
- [[agent-session-completion-signals]] — **Nothing an agent session leaves behind reliably says "I am finished", and every cheap proxy for done-ness fails toward "done"** (2026-08-23, [[agent-factory]]). Three completion signals tried in one evening, all three wrong: **file existence** — `dispatch._answered_ids()` globs, so R17 flipped to `ANSWERED` on its first byte and then grew **13 KB**, unlocking a dependent pass that would have audited a two-thirds-written answer and *silently produced a worse one*; **process exit** — the `claude` CLI **stays resident** after finishing, so a watcher polling for it never fired at all (and a `wt` pid is not the session's pid, which is why `task_claim` records no pid and fails closed); **mtime stability** — a 60-second quiet window plus a green gate declared done, and the session then wrote **751 more lines**, taking the file 80,565 → 143,989 bytes *after* the commit that claimed to contain it. ⭐ **A quiet window measures the agent's rhythm, not its progress**, and a gate turning green is not a completion signal either — a partial artefact can satisfy the gate's own condition. Completion is a claim only the worker can make; nothing in this estate builds that declaration yet. Carries the rule *never commit an artefact a live session owns*, and the cheapest instrument of all: **ask the human who can see the terminal**. - [[conclave-pr-review]] — `/conclave` Claude Code skill (Paul, 2026-07-29). **Adversarial multi-lens PR review** — a council of 5 independent reviewers (correctness/data-flow · security & tenancy · ticket-acceptance/root-cause · adversarial red-team · tests/verification) on the same diff, blind to each other, then deduped and **re-verified against real code by the synthesiser before a human reads it**. Highest-yield mechanic = **feed members your own hypotheses inviting refutation** (killed 5 wrong orchestrator leads in the reference run). - [[inquest-bug-resolution]] — `/inquest` Claude Code skill (Paul, 2026-07-29). **Adversarial multi-lens bug resolution** — sibling to [[conclave-pr-review]]: conclave reviews a *change*, inquest resolves a *defect*. Council of 5 locked to orthogonal layers (symptom/scope · consumer-render · data & query · code path · falsifier), blind to each other, then a synthesiser that **re-runs every root-cause claim before a human reads it**. WHERE status='queued' RETURNING` — zero `SKIP LOCKED` in the whole tree), **session identity keyed `(agent, task)` not `(agent)`** (the difference between resuming and restarting), a **content-hashed skill bundle** passed to `--add-dir` that keeps the prompt cache warm *and* correctly invalidates resume, and `cost_status: unpriced|reported`. ⛔ **Four README claims that do not survive the code** — *"checkout and budget enforcement are atomic"* (checkout true, budget a textbook TOCTOU); **no per-model pricing table exists anywhere**, and adapters returning `costUsd: null` burn real tokens while counting as zero in a system that labels them `"unpriced"` then sums without filtering (see [[vacuous-verification]]); no task lease/TTL (the lock timestamp is written six times and never compared); and a single-server design documented nowhere. ⭐ **The worktree/sandbox boundary, stated exactly:** *a worktree suffices while the worst outcome is losing work you can regenerate; a sandbox is warranted when it reaches something you cannot* — production credentials, a client's warehouse, the shared git object store, or an unbounded bill — so **the gap to close first is credentials, not isolation.** Three traps that cost time: Paperclip's default branch is `master` not `main`; SSSF drives `pi` and its Claude Code adapter is a `NotImplementedError` stub; web search wrongly attributes **E2B** to Inkwell (that is `disler/agent-sandboxes` — Inkwell uses exe.dev VMs over plain SSH). ⚠ **None of the three is measured** — no evals, no benchmarks, no cost baseline; the rationale is unusually well argued, but arguments are not evidence.

- [[classifier-recalibration-pattern]] — Getting an LLM classifier from "measured but wrong" to "safe and accurate" without retraining or threshold tuning. Three moves: (1) prove the auto-action is safe first via a persisted per-row **noise-FPR gate** (asymmetric-cost error as a hard gate, not aggregate accuracy); (2) fix the dominant confusion with **deterministic levers** — a fail-open pre-filter that excludes high-cost cases + a cost-asymmetry band cap (not a global threshold move); (3) defer post-hoc calibration until model inputs (grounding) are informative.
