# What the Agent Runner Does

It connects your **workflow engine → OpenClaw agents**.

Example lifecycle:

POST /tickets  
      │  
      ▼  
workflow_run created  
      │  
      ▼  
state: TICKET_INTAKE  
      │  
      ▼  
Agent Runner  
      │  
      ▼  
OpenClaw executes IntakeAgent  
      │  
      ▼  
artifact created  
      │  
      ▼  
workflow_events updated  
      │  
      ▼  
next state triggered

That’s the **core intelligence loop**.

# Step 1 — Create Agent Runner Service

Create a new file:

api/app/services/agent_runner.py

This will:

1. Inspect workflow state
    
2. Map state → agent
    
3. Trigger OpenClaw
    
4. Track session
    

Example mapping:

STATE_AGENT_MAP = {  
    "TICKET_INTAKE": "IntakeAgent",  
    "DESIGN": "DesignAgent",  
    "PROFILING": "ProfilerAgent",  
    "BUILD": "BuilderAgent",  
    "QA": "QAAgent",  
    "PR_CREATION": "PRAgent"  
}

---

# Step 2 — OpenClaw Client

Create:

api/app/services/openclaw_client.py

This service will:

connect to ws://openclaw:18789  
create agent session  
stream events  
return results

You do **not** want agent logic in the orchestrator.

Only **triggering + tracking**.

---

# Step 3 — Integrate Runner Into Workflow Engine

Inside your orchestrator logic:

orchestrator.py

When a state begins:

enter_state()

call:

agent_runner.run_for_state(...)

# Important Question You Asked

Not yet.

Once the **Agent Runner exists**, then OpenClaw agents can help generate:
