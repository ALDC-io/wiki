### FU92-394 — Viant DSP Connector Timeout Fix (Bug)

Juliann reported Viant actuals missing after April 2. Root cause: the `get_completed_reports()` polling loop in `viant_dsp_reporting.py` had no timeout or max retry — when the Viant API returned a non-terminal status, the connector hung indefinitely, blocking the entire worker queue. Schedules were disabled to unblock the queue and never re-enabled.

**Code fix applied (Phase 1):**
- Added `MAX_POLL_ATTEMPTS` cap to polling loop
- Terminal status detection (Failed, Error) — breaks instead of looping forever
- HTTP 429 rate-limit handling with backoff
- Timeout/retry on CSV download (`pandas.read_csv(url)`)

**Automatic deployment wired up:** FU92-394 will deploy through the new CI pipeline (GitHub Actions → self-hosted runner → Docker build → GHCR push) set up on 2026-05-03 for the legacy connector repo. Code fix is implemented but unstaged on `development`. Unit tests not yet written — next session.
