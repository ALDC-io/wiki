### GP-199 — ASIN Brand Campaign Attribution (Implementation Complete ✅)

Full implementation done in this session. Branch: `feature/paulrussell/gp-199/asin-brand-campaign-attribution`

**Changes written:**
- **Connector** (`amazon_ads.py`): added `SPONSORED_BRANDS_ADS_LIST_ENDPOINT` + `"ad"` category handler. Key finding: connector's `remove_all_lists()` strips Python lists — serialized `creative["asins"]` as JSON string so it survives as `CREATIVE_ASINS VARCHAR` in Snowflake.
- **Eclipse templates** (2 new): `sponsored_brands_ad.json` (full partition, daily ad metadata) and `sponsored_brands_ad_report.json` (date partition, min_date 2026-05-01).
- **Warehouse SQL** (3 files): `extract_amazon_ads_sb_ad_asin_map.sql` (queries `COMBINED_SPONSORED_BRANDS_AD` with validity range `VALID_FROM`/`VALID_UNTIL`), `extract_amazon_ads_sb_ad_daily_spend.sql` (Step 1 equal split), `marketing_fct_activity.sql` (SB section rewritten as 3-part union: ASIN-attributed + non-ASIN fallback + pre-go-live legacy).
- Deploy + validate manifests created.

**Key design discovery:** `COMBINED_*` is a SECURE VIEW (UNION ALL of versioned tables), not a physical table. `merge_strategy=add` only inserts on change — not every run. Validity range join (`VALID_FROM <= date AND VALID_UNTIL > date`) is required for correct historical attribution; a snapshot-only join would incorrectly include removed ASINs for post-removal dates.

**Blocked on:** Eclipse templates need to be deployed + run at least once before `COMBINED_SPONSORED_BRANDS_AD` and `CURRENT_SPONSORED_BRANDS_AD_REPORT` exist in Snowflake — sandbox SQL deploy can only run after that.
