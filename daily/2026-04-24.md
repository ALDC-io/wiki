# Daily Notes Template

Copy this file as `YYYY-MM-DD.md` (e.g., `2026-04-17.md`) and add notes throughout the day. When ready, ask Claude to "ingest today's notes" — it will read each entry and update the correct wiki pages.

---

## How to use

Each note is a `## Note` block with a `type:` tag. Write naturally — the type tag tells Claude where the note belongs in the wiki.

**Types:**

| Type | Where it goes | Use when... |
|------|--------------|-------------|
| `ticket` | `tickets/gep/GP-XXX.md` or similar | Decisions, findings, blockers, progress on a ticket |
| `process` | `processes/deployment/` or `operations/` | Steps you followed, pitfalls hit, process improvements |
| `business-logic` | `concepts/business-logic/` | Client rules, domain knowledge, data definitions |
| `decision` | Relevant ticket or concept page | You made or learned about an architectural/design choice |
| `bug` | New or existing concept/ticket page | A bug you found, root cause, fix |
| `tool` | `entities/tools/` | Something you learned about Snowflake, PBI, Eclipse, etc. |
| `client` | `entities/clients/` | Client context, contacts, environment info |
| `idea` | Depends on content | Feature ideas, improvement suggestions |
| `general` | Claude decides based on content | Anything that doesn't fit above |
| `action` | `action-items.md` (appended to Open) | You want to guarantee a TODO is captured — use this when prose might be ambiguous |

**About action items:** During ingest, Claude automatically scans *every* note (regardless of type) for natural-language action items ("need to...", "remember to...", "follow up on...", imperatives, etc.) and adds them to `action-items.md`. Use `type: action` when you want guaranteed capture for something critical, or when prose phrasing might read as commentary rather than a TODO.

**Minimal format:**

```markdown
## Note
type: ticket
ref: GP-208

Client confirmed data share is the delivery mechanism. Snowflake account: XYZ123.
Refresh cadence is daily at 6am EST. CaptureDate is UTC.
```

That's it. You don't need headers, formatting, or complete sentences. Just the type, an optional ref (ticket ID, tool name, client name), and your note.

## Example daily file

```markdown
# 2026-04-17

## Note
type: ticket
ref: GP-208

Client confirmed: data share (not CSV). Account locator is GEP-NAVIRA.us-east-1.
Refresh daily at 6am UTC. CaptureDate is UTC. Iteration = batch counter, increments by 1.
AWD = Amazon Warehousing & Distribution. Kit columns are placeholders for now.

## Note
type: process
ref: deployment

Learned the hard way: always check if Snowflake tasks are paused BEFORE deploying new views.
If you deploy a view that a running task depends on, the task fails silently and you get stale data.

## Note
type: business-logic
ref: GEP

DTC fee (3%) only applies to orders from direct-to-consumer marketplaces (Shopify, WooCommerce).
Amazon orders never get a DTC fee. This is controlled by IS_DTC_MARKETPLACE flag in shared_dim_marketplace.

## Note
type: decision
ref: GP-208

Going with Option A grain: MASTER_SKU x CaptureDate. Iteration is metadata only.
Append-only table with extract view filtering to MAX(CAPTURE_TIMESTAMP).

## Note
type: tool
ref: Snowflake

EQUAL_NULL(a, b) treats NULLs as equal — use instead of COALESCE(..., 'sentinel') comparisons.
Much cleaner for join conditions where either side can be NULL.

## Note
type: general

Steven is on vacation next week (Apr 21-25). I'm covering Fusion92 PR reviews.

## Note
type: action
ref: GP-208

Put Power BI model back in GitHub after manual deployment — keep getting bitten by forgetting this step.
```

When you tell Claude "ingest today's notes", it will:
1. Read the daily file
2. For each `## Note` block, identify the target wiki page from `type:` + `ref:`
3. Update that wiki page with the new information (or create one if needed)
4. Add cross-references via `[[wikilinks]]`
5. Update `index.md` if any new pages were created
6. Append to `log.md`
7. The daily file itself stays in `daily/` as a permanent record.
