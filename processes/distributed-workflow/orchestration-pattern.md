# Orchestration Pattern

Coordination model for parallel Claude Code sessions sharing one wiki (or one set of repos). Extends [[CLAUDE|Parallel Ingestion]] from the page level (subagents within a session) to the session level (multiple Claude instances over a day).

## The pattern in one paragraph

Each workstream gets one **tracker file** in `processes/distributed-workflow/active/`. A session is the **single writer** for its workstream's tracker and for files inside its declared **lane**. Edits to **shared files** (`index.md`, `log.md`, `action-items.md`, the day's daily note) are not made directly during the session — they're written into the tracker's *Pending Wiki Updates* section and applied at end-of-day in a single mechanical merge pass. Cross-lane work stops the session and writes a *Cross-Lane Request* into the tracker for human triage.

## Lanes (write isolation)

A **lane** is the list of paths a workstream is allowed to write to. Sessions read freely across the wiki but write only inside their lane.

### Today's lanes

| Workstream | Wiki | Owned paths |
|---|---|---|
| Confluence migration | ALDC | `sources/`, new pages under `entities/`, `processes/`, `concepts/` *that originate from Confluence sources*, plus `processes/operations/confluence-migration.md` |
| Client workflow automation | ALDC | `entities/projects/workflow-automation.md` (new), `concepts/patterns/sandbox-feature-delivery.md` (new). **Read-only** on existing GEP runbooks until a written design lands |
| Zeus Memory ingestion | ALDC | `processes/distributed-workflow/active/zeus-memory/` (tracker + phase pages), `entities/projects/zeus-memory.md` (product entity). **Read-only** on CCE and other project pages. |
| Neurospect | Neurospect wiki **only** | `entities/projects/neurospect.md`, `concepts/business-logic/ict-*`, `sources/neurospect/`. **Strictly forbidden from writing anywhere in the ALDC wiki.** |

Lanes are declared in each tracker's *Lane* section. If a session needs to write outside its lane, it stops and writes a *Cross-Lane Request* in its tracker.

### Cross-wiki rule

The Neurospect wiki is fully decoupled from the ALDC wiki. The single allowed coupling is one-way: Neurospect may **read** the three pattern docs in this folder (`README.md`, `orchestration-pattern.md`, `session-lifecycle.md`, `tracker-template.md`) **by absolute path**, never by wikilink. Nothing else crosses. The ALDC wiki never references Neurospect.

## Shared-file protocol

These files are written by every workstream and need single-writer discipline:

- `index.md`
- `log.md`
- `action-items.md`
- `daily/YYYY-MM-DD.md`

**Protocol:** during a session, append the proposed change as a markdown block in the tracker under *Pending Wiki Updates*. At end of day (or when the wiki needs to be coherent for an outside reader), open a short **merge session** that walks each active tracker, applies the pending updates to the shared files, and clears the *Pending* sections. Merge sessions are mechanical — no plan mode, no ambiguity.

**Exception:** the daily note's `## Distributed Workflow Checkpoint` block is appended directly by the session at checkpoint time. It's structured, additive, and never conflicts because each session writes its own sub-block.

## Performance techniques to leverage in Claude Code

These are session-internal moves that compound across parallel work:

- **Explore subagents for reads.** Keeps the main session's context lean so each session can re-bootstrap cheaply on the next handoff. Especially useful when a tracker references many entity pages.
- **Plan agents for design validation.** When a session's scope is fuzzy or there are multiple viable approaches, have a Plan agent validate before committing.
- **Parallel tool calls.** Issue independent reads in a single message. The cumulative latency saving across a day of parallel sessions is significant.
- **Plan mode = handoff artifact.** The plan file generated by plan mode is the cleanest cross-session handoff vehicle. Pair it with a tracker checkpoint and the next session boots with zero context guessing.
- **TaskCreate vs trackers.** TaskCreate tracks progress *within* a session. Trackers track progress *across* sessions. Don't conflate — TaskCreate state evaporates at session end; trackers persist.
- **Auto-memory for durable preferences.** User profile, feedback, project facts. Trackers hold ephemeral workstream state; auto-memory holds the things that should outlive any single workstream.

## Conflict avoidance

Lanes are agreed upfront in this folder's tracker files and in [[README]]. If a session discovers it needs to write outside its lane:

1. Stop the in-flight work.
2. Write a *Cross-Lane Request* in the tracker: `### Cross-Lane Request — YYYY-MM-DD HH:MM` followed by what you wanted to change, why, and which other workstream's lane it belongs to.
3. Surface to Paul. Don't merge across lanes silently.

This is the same instinct as the no-silent-overwrite rule in [[CLAUDE]] § *Rules* #6 (contradictions get flagged, not silently resolved).
