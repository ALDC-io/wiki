## Initial Analysis

### What logout/login NOT fixing rules out
~~The known JWT session caching issue (stale role claims persist until logout) is ruled out. The problem is deeper.~~ **Update 2026-05-07:** It WAS JWT session caching — but deeper than expected. The parent Eclipse portal mints the JWT, so logging out of just DAX doesn't help. CosmosDB was correct (`buyer`), but the JWT callback never re-fetched roles. Fixed in [[FU92-396]].

### Likely causes (ranked)

1. **Role actually wrong in core_api/CosmosDB** — the role stored in the backend doesn't match what Ken needs
2. **Status-specific permission bug** — "approved" flights may gate certain actions to specific roles (Super Admin, Admin) that Ken doesn't have
3. **Flight-data issue** — something about this specific flight's data causes a rendering/API error unrelated to permissions
4. **Recurring platform bug** — Juliann's "another instance" comment suggests this has happened before with other users/flights

### Architecture: How DAX auth works

- **4 roles**: Super Admin (full access) → Admin (no field-type changes) → User (own jobs only) → Buyer (spend input, pacing)
- **Auth flow**: core_api → NextAuth JWT (`is_admin`, `is_internal`, `applications`, `groups`) → Session → Frontend components
- **Role storage**: core_api/CosmosDB user record
- **Frontend checks**: `session.user.is_admin`, `session.user.applications` in React components
- **Backend checks**: DAX API endpoints in `workflows/fusion_92/F92_workflow_app`, account-ID gating on NetSuite endpoints

### Key code locations

| What | Where |
|------|-------|
| Auth config / JWT callbacks | `flight-check` repo → `authOptions.ts` |
| Role-gated UI | `flight-check` repo → `metadata/Job.json`, `admin.json` |
| DAX API endpoints | `workflows/fusion_92/F92_workflow_app` → HTTP routes |
| User management | Eclipse portal → manage_team → core_api |
| Account-ID gating | DAX API → checks `body.account_id == FUSION_ACCOUNT_ID` |
