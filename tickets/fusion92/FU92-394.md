# FU92-394 — Viant DSP Actuals Missing After 4/2

Viant flights in DAX are not reporting actuals after April 2, 2026. Reported by client (Juliann) — reporting due this week.

## Status

Phase 1 complete (code fix). Phase 1b CI green — `:development` image ready. Targeting Phase 1b deploy → Phase 2 re-enable + backfill → Phase 3 validate today (2026-05-08). Client emailed with ETA. Also created FU92-398 for separate Meta discrepancies reported by Juliann on 2026-05-07.

## Problem

All three `viant_dsp_reporting_v1` templates in Eclipse 1 are `inactive`:
- Viant DSP - Campaign Performance Report
- Viant DSP - Campaign ROAS Report
- Viant DSP - Conversion Report

The fourth Viant template (Reach and Frequency - Fusion Snowflake) uses `snowflake_v1` and is still active but has its own failure pattern (550/73/0).

## Root Cause

The `viant_dsp_reporting` connector's polling loop (`get_completed_reports()` at `connector/viant_dsp_reporting.py:149`) has no timeout or max retry. When the Viant API returned a non-terminal status, the connector hung indefinitely, blocking the entire worker queue on the Kamloops server.

To unblock the queue, Viant connector schedules were disabled in Eclipse 1. The intent was temporary ("if everything working tomorrow remove schedule block") but the schedules were never re-enabled.

Prior incident documented at: `sources/obsidian-import/learning/bugs/viant_dsp_reporting`

## Fix Plan

### Phase 1: Code hardening (before re-enabling)
1. Add `MAX_POLL_ATTEMPTS` cap to `get_completed_reports()` polling loop
2. Handle non-"completed" terminal statuses (Failed, Error) — break instead of looping
3. Add HTTP 429 rate-limit handling with backoff
4. Add timeout/retry to CSV download (`pandas.read_csv(url)` at line 186)

### Phase 2: Re-enable and backfill
1. Re-enable three Viant DSP template schedules in Eclipse 1
2. Trigger manual backfill for April 2 → present
3. Validate actuals appear in DAX

### Phase 3: Validation
1. Confirm data freshness in Snowflake (`MAX(date)` on Viant tables)
2. Verify actuals visible in DAX flights
3. Monitor connector runs for 24-48hrs for stability

### Phase 4: Close out
1. Update this Jira ticket with resolution steps
2. Send client communication (via Lori)
