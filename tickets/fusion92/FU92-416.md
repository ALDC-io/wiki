# FU92-416 — Investigate Trade Desk + Viant Auth Token Lifespan

**Status:** To Do
**Priority:** Medium
**Jira:** https://analyticlabsdc.atlassian.net/browse/FU92-416

## Summary

Full connector token audit (2026-05-21) identified two active Fusion92 connectors with undocumented auth token lifespans and no automated refresh. Both connector source files explicitly note the token lifespan is unknown.

| Connector | Templates | Auth Type | Connection ID |
|---|---|---|---|
| `trade_desk_my_reports_v1` | 2 (performance + unique impressions) | Static `auth_token` (Base64) | `2aa7e056-28f9-4bf9-9758-3fdc7217409d` |
| `viant_dsp_reporting_v1` | 2 (campaign perf + ROAS) | Basic auth `auth_token` (Base64 user:pass) | `a73a6943-8276-4490-a3d4-9734a0024413` |

## Investigation Plan

### Phase 1: Determine token lifespans

**Trade Desk:**
1. Check Trade Desk My Reports API docs for auth token expiry policy
2. Check CosmosDB `_ts` on connection doc `2aa7e056` to determine token age
3. Check Trade Desk portal for token creation/expiry dates
4. Contact Trade Desk support if docs are ambiguous

**Viant:**
1. Check Viant DSP Reporting API docs for Basic auth credential rotation policy
2. The `auth_token` is Base64-encoded `username:password` — check if password has an expiry policy
3. Check Viant portal for credential management settings
4. Contact Viant support if docs are ambiguous

### Phase 2: Assess risk

For each:
- How old is the current token? (CosmosDB `_ts`)
- Has it ever stopped working due to auth expiry? (check Eclipse schedule history for 401/403)
- What's the blast radius? (downstream tables + reports)

### Phase 3: Implement refresh (if needed)

**If Trade Desk tokens expire:**
- Implement refresh workflow following [[FU92-246]] / [[FU92-415]] pattern
- If static API key that doesn't expire → document and close

**If Viant credentials expire:**
- Implement automated password update, or document rotation procedure
- If static → document and close
- Note: Viant already had a major outage ([[FU92-394]]) — monitoring prevents compounding failures

### Phase 4: Add monitoring

Regardless of expiry, add to observability freshness monitoring:
- Alert if either connector goes >48h without a successful run
