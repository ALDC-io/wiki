## Issue 1: Token Refresh Automation

`facebook_business_v1` connector has no auto-refresh for Meta long-lived tokens (~60-day expiry). The April 2026 gap was partly caused by this. Direct API connector (RBA) relies on manually refreshed token in Eclipse connection `1df7d48a`.

**Precedent:** [[FU92-246]] automated Microsoft Ads token refresh using Eclipse task system (assigned to Steven Deutekom).

### Token refresh approach (Meta-specific)

```python
# Exchange current long-lived token for a new one
GET https://graph.facebook.com/{version}/oauth/access_token
  ?grant_type=fb_exchange_token
  &client_id={app_id}
  &client_secret={app_secret}
  &fb_exchange_token={current_long_lived_token}
```

Unlike MS Ads (which uses OAuth2 refresh tokens), Meta's long-lived tokens are refreshed by re-exchanging them before expiry. The refresh window is: token must be exchanged when it's at least 24 hours old but before the ~60-day expiry.

## Final Fix (2026-05-22)

The RBA double-count fix was refined to preserve historical data:

```sql
-- RBA direct data included ONLY before Windsor coverage
FROM META.CURRENT_AD_SET_RBA_AD_SET_INSIGHTS
WHERE DATE_START::DATE < '2025-08-04'
```

Windsor covers RBA from 2025-08-04 onward. Direct API has data from 2023-10-02 that Windsor does not. The date filter preserves 15,266 rows ($565K) of historical spend while eliminating the double-count on recent data.
