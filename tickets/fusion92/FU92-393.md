# FU92-393 — Fusion NetSuite Sandbox Connection Failure

- Jira: FU92-393 (analyticlabsdc.atlassian.net, cloudId 239c1bf0-93f4-4201-95fe-ab73ce4a6eff)
- Link: https://analyticlabsdc.atlassian.net/browse/FU92-393
- Status: QA — auth fix verified, E2E UI test pending
- Priority: Normal

## Summary

NetSuite PO sync returns 500 `{"error": "server_error"}` in QA (sandbox) but works fine in production. The issue is at the OAuth M2M token endpoint — authentication fails before any API calls are made.

## Root Cause

**Wrong Client ID stored in the Azure Function App env var.** The original integration ("ALDC App Connection", created 2025-07-29) had its Consumer Key shown only once at creation. The value stored in `NETSUITE_CLIENT_ID` on `aldctestfnapf921c01` did not match the actual Consumer Key. The execution log on the integration was completely empty — it had never successfully authenticated.

## Fix Applied (2026-05-25)

1. Created new integration **"ALDC App Connection v2"** in NetSuite sandbox
2. Generated new public certificate from existing EC P-256 private key (valid until 2028-05-22)
3. Created new M2M setup entry linking cert → v2 integration → Analytic Labs user → Administrator role
4. Updated Azure Function App `aldctestfnapf921c01` (Test 1 subscription):
   - `NETSUITE_CLIENT_ID` → new Consumer Key from v2 integration
   - `NETSUITE_CERTIFICATE_ID` → new certificate ID from M2M setup
   - Added missing `NETSUITE_PO_PROJECT_MANAGER_ID` (was absent, present on prod)
   - Added missing `NETSUITE_PO_CLIENT_LEAD_ID` (was absent, present on prod)
5. Updated `aldcdevfnapfusion2c01` (Development 2) with same sandbox credentials — but DEV function app returns empty 500 (runtime crash, separate issue)
6. Redirected Eclipse QA portal (`aldcqanode1c01`) `F92_NETSUITE_SYNC_URL` from DEV → TEST function app as workaround

## Verification

- Direct OAuth token request to sandbox: **200 OK** (was 500)
- SuiteQL query via TEST function app (`GET /api/f92_netsuite_publishers`): **200 OK**, returned 2,263 vendors
- All employee IDs verified present in sandbox (PM 2747, Client Lead 13417, ALDC Employee 13456)

## Remaining (2026-05-26)

1. **E2E UI PO sync test** — flight `netsuite_sync` status is stuck at "broken" after unlocking; need to reset it (core_api `account_describe` crashes on any user operation when account doesn't match)
2. **DEV function app** (`aldcdevfnapfusion2c01`) returns empty 500 — runtime crash before code executes, separate issue from credentials
3. **Eclipse QA portal wiring** — `F92_NETSUITE_SYNC_URL` was changed from DEV → TEST as workaround; decide if this should be permanent
4. **QA core_api issues** discovered during testing:
   - `users/login` route (plural) doesn't match core_api's `user` (singular) route — Eclipse 2.1 code uses plural but core_api expects singular
   - `user/login` route is gated behind auth check (`check_auth_service("portal")`) requiring Bearer master token — unauthenticated login is impossible without the Eclipse proxy adding the token
   - `account_describe` crashes on empty/invalid account IDs instead of returning gracefully — blocks all user operations (read, update, delete) when the account doesn't exist
   - Paul's QA user created: `paulrussell@aldc.io` / `aldc1234` (account `f49f9aa3`)
