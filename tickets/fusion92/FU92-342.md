# FU92-342 — Viant Campaign Conversions Fact Table

Build `fct_campaign_conversions` dynamic table for [[fusion92]]. Key challenge: Viant adapter was producing duplicate rows, requiring investigation into root cause and proper deduplication strategy.

## Status

In progress — PR review cycle with Steven (senior dev).

## Problem

The Viant conversion data source (`VIANT.CURRENT_CONVERSION_REPORT_CAMPAIGN`) contained duplicate rows at the grain of `(ADVERTISER_ID, CAMPAIGN_ID, ORDER_ID, CONVERSION_EVENT_ID, DATE)`. 426 duplicate groups found in January 2026 data.

## Root Cause

`CONVERSION_EVENT_ID` was **missing from the primary key** in the connector template. Without it, the connector couldn't distinguish between unique conversion events for the same campaign/order/date, causing duplicate rows to persist through ingestion.

## Resolution

1. Added `CONVERSION_EVENT_ID` to PK in the connector template
2. Re-ran the adapter and confirmed zero duplicates via audit query
3. Replaced `COALESCE(..., 'NO_ORDER')` equality checks with `EQUAL_NULL` for cleaner null comparisons

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Source table | `VIANT.CURRENT_CONVERSION_REPORT_CAMPAIGN` (not `VIANT.CONVERSION_REPORT_CAMPAIGN`) | Use `CURRENT_*` prefix per ALDC convention |
| Deduplication strategy | Fix at source (PK), not aggregate in fact | Aggregating hides data issues and can skew conversion values |
| Schema location | `WAREHOUSE` (not `WAREHOUSE_UTILITY`) | Per team decision |
| Flight-ID CTE reuse | Deferred to follow-up ticket | `PLATFORM_*` and `FLIGHT_PLATFORM_IDS` CTEs duplicated in both `fct_platform_spend` and `fct_campaign_conversions` — refactor planned |

## Duplicate Audit Query

```sql
WITH base AS (
    SELECT
        ADVERTISER_ID::VARCHAR AS platform_account_id,
        CAMPAIGN_ID::VARCHAR AS platform_campaign_id,
        ORDER_ID::VARCHAR AS platform_order_id,
        CONVERSION_EVENT_ID::VARCHAR AS conversion_id,
        TO_DATE("DATE", 'MM/DD/YY') AS conversion_date,
        CONVERSIONS::FLOAT AS conversions
    FROM VIANT.CURRENT_CONVERSION_REPORT_CAMPAIGN
),
dup_check AS (
    SELECT platform_account_id, platform_campaign_id, platform_order_id,
           conversion_id, conversion_date,
           COUNT(*) AS row_count,
           COUNT(DISTINCT conversions) AS distinct_conversion_values
    FROM base
    GROUP BY 1,2,3,4,5
    HAVING COUNT(*) > 1
)
SELECT * FROM dup_check WHERE distinct_conversion_values > 1;
```

Post-fix: returns zero rows.
