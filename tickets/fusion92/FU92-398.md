# FU92-398 — Meta Data Discrepancies Across All Clients for April

**Status:** Ready for Customer (investigation complete)
**Priority:** High
**Reporter:** Juliann Otto (j.otto@fusion92.com) — Associate Director, Media Ops
**Raised:** 2026-05-07

## Summary

Juliann reported Meta data showing discrepancies across all Fusion92 clients for April 2026. Requested we triple-check nothing similar to the Viant outage ([[FU92-394]]) is affecting Meta, and confirm whether a data refresh is needed.

## Investigation

### Data Integrity — Confirmed Clean

- All 30 April days present in `META.FACEBOOK_AD_INSIGHTS_1`
- 37,188 rows, $1.92M total spend
- All rows CURRENT=1, DELETED=0 — zero overwrites, zero deletions
- All major accounts show 30/30 April days with no gaps

### Root Cause — Connector Loading Gap

A **25-day gap in connector loading** occurred from April 5 to April 28:

| Period | Action | Rows |
|---|---|---|
| Apr 1–4 | Normal daily loading | ~4,267 |
| **Apr 5–28** | **No connector runs** | **0** |
| Apr 29 | Backfill caught up (Apr 4–29) | 29,631 |
| Apr 30+ | Resumed daily loading | Normal |
| May 6 | Late backfill (Apr 15–30) | 287 |

Data is complete now but was loaded ~25 days late. Anyone checking dashboards during April 5–28 would have seen data stopping at April 4. This is likely what triggered the discrepancy report.

### Spend Analysis — March vs April

Monthly spend trend: Jan $2.80M → Feb $2.17M → Mar $2.38M → **Apr $1.92M**

The ~19% aggregate drop is driven by campaign volume changes, not data loss:

| Account | March | April | Trend |
|---|---|---|---|
| Fusion92 - Evergreen Media | $1,406,083 | $990,584 | Down (campaign volume) |
| BCBSM Business Units - DP+ | $143,044 | $184,052 | Up |
| Smile Doctors | $579,209 | $456,351 | Down |
| Brookfield Zoo - Temp | $14,722 | $47,139 | Up |
| All other accounts | Stable | Stable | — |

### Campaign Continuity

- 30 campaigns ended between March and April — natural lifecycle (events, budget cycles)
- 30 campaigns show mid-month gaps — all Fusion92 Evergreen Media dental practices with low budgets ($200–$2,700), intermittent pacing by design
- Tamarack-Temp (16 days) and Dremel (11 days) are new campaigns started mid-April

### Google Ads — Healthy

Spot-checked per Juliann's mention of Google Ads issues (~May 5):
- CAMPAIGN_9: current through 2026-05-08, March 146k rows vs April 113k (volume, not loss)
- CAMPAIGN_10: current through 2026-05-04 (runs every 2 days)

### BCBSM Ad Set Connectors — Separate Finding

Three ad set-level tables stopped loading on 2025-09-19:
- AD_SET_BCBSM_BRAND_DP_AD_SET_INSIGHTS
- AD_SET_BCBSM_BUSINESS_UNITS_DP_AD_SET_INSIGHTS
- AD_SET_BCBSM_MICHIGAN_AD_SET_INSIGHTS

**Not required.** No active views, tables, or procedures consume these. Only SQL reference is in `FUSION_92/snowflake/deprecated/`. BCBSM campaign data flows correctly through the main connector.

## Resolution

No data loss. No refresh or backfill needed. Data is complete and accurate.

Email draft for client provided to Lori (EI Lead) via Jira comment.

## Follow-up Investigation (2026-05-21)

Full diagnostic re-run against `PROD_DG1_FUSION_92` confirmed the April gap is fully resolved and no data was lost. Findings:

| Path | Status | Last data | Notes |
|---|---|---|---|
| Windsor (BCBSM + 20 accounts) | Healthy | 2026-05-21 | No gaps in 90d, 1.9M rows |
| Direct API — RBA | Healthy | 2026-05-21 | No gaps |
| Direct API — CCCU | Dead | 2023-11-27 | Set to inactive (no campaigns since Nov 2023) |
| Direct API — PCU | Dead | 2023-11-13 | Set to inactive (no campaigns since Nov 2023) |
| Smile Doctors (Windsor) | Winding down | 2026-05-09 | Campaign lifecycle, not connector issue |

**Root cause of the April 5–28 gap confirmed:** The Viant queue blockage ([[FU92-394]]) prompted a schedule disable of "all fusion connections" in Eclipse 1. Meta schedules were caught in this sweep. Combined with a ~60-day token expiry with no auto-refresh. Windsor self-recovered via backfill on April 29.

**New ticket created:** [[FU92-415]] — Meta Connector: Token Refresh Automation + Template Cleanup. Covers automated token refresh, CCCU/PCU template cleanup, and connector monitoring.

### Second Follow-up (2026-05-22)

Juliann reported two ongoing discrepancies despite the token refresh fix:

1. **Ross Brand (6ROSS):** DAX $18,378 vs Meta $10,780 — DAX ~1.7x higher. Root cause: RBA (609816340424519) was in BOTH the direct API table and Windsor, doubling spend in `ALL_META_AD_SET_INSIGHTS`. **Fixed** — removed RBA direct block, added date-filtered historical preservation (`WHERE DATE_START < '2025-08-04'`). No data lost.

2. **Smile Express (6Q2SE):** DAX $182,580 vs Meta $187,638 — DAX lower. Root cause: Smile Doctors account disconnected from Windsor portal since May 1. Confirmed via direct Windsor API call (account missing from response). **Needs Windsor re-authentication** by Fusion team. Email sent to Lori/Juliann.

All direct Meta API ad_set templates now `inactive` across TEST + PROD CosmosDB. Windsor is sole active source.
