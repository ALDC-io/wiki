# FU92-397 — NetSuite PO Employee Field Shows Wrong Person

- Jira: FU92-397 (analyticlabsdc.atlassian.net, cloudId 239c1bf0-93f4-4201-95fe-ab73ce4a6eff)
- Link: https://analyticlabsdc.atlassian.net/browse/FU92-397
- Status: Deployed to Production — Awaiting Client Confirmation
- Priority: High

## Summary

When POs are created from DAX via "Sync with NetSuite", the **Employee** field on the PO shows the wrong person. The Employee should reflect the user who triggered the sync, but instead it shows the **project manager assigned to the NetSuite project (job)**.

## Reporter

Juliann Otto (j.otto@fusion92.com) — reported 2026-05-05 via email to support@aldc.io.

## Example

- PO001188 (CNS Media B.V.)
- Flight created by: Michael Child
- Synced by: Noah Elliot
- Employee shows: **Tom Hammond** (incorrect)
- Other cases show Julie Cahill, etc.
- Juliann and Noah (most common sync users) rarely appear correctly.

## Root Cause

**Code path:** `workflows/netsuite.py` → `F92NetsuitePOWorkflow.build_po_request_body()` → line 496

```python
"employee": {"id": project_manager_id},
```

Where `project_manager_id = ns_project["projectmanager"]` (line 455) — the **project manager of the NetSuite project**, not the syncing user.

**Why it varies per PO:** Different jobs map to different NetSuite projects, which have different project managers. Tom Hammond is PM for one project, Julie Cahill for another, etc.

**Why `ALDC_NETSUITE_EMPLOYEE_ID` doesn't help:** The env var (line 231) is declared but **never referenced** anywhere in the code — dead code. It was apparently intended as a fallback but never wired in.

**Why no user identity is available:** The sync request from the frontend sends only `{account_id, flight_id}` — no user identity is passed. The backend has no way to know who clicked "Sync with NetSuite".

## Proposed Fix

**Status:** IMPLEMENTED — PRs Raised 2026-05-22

Client confirmed fix approach on 2026-05-11 (employee = syncing user, all users are NetSuite employees).

**Implementation:**

1. **Frontend** (`flight-check/pages/api/netsuite/sync/syncpo.ts`):
   - Use `getServerSession()` to extract the logged-in user's `first_name` and `last_name`
   - Pass them to the backend alongside `account_id` and `flight_id`

2. **Backend** (`workflows/netsuite.py`):
   - Accept `user_first_name` and `user_last_name` from the request
   - Look up the matching NetSuite employee via SuiteQL: `SELECT id FROM employee WHERE firstname = '...' AND lastname = '...'`
   - Use that employee ID for the PO's `employee` field
   - Fallback to `ALDC_NETSUITE_EMPLOYEE_ID` env var if no match found
   - Second fallback: project manager (original behavior)

3. **Backend** (`function_app.py`):
   - Pass user name fields through to the workflow

**Affected files:**

| Repo | File | Change |
|---|---|---|
| `workflows` | `workflows/netsuite.py:496` | Use syncing user's NS employee ID instead of project PM |
| `workflows` | `workflows/netsuite.py:231` | Wire up `NETSUITE_EMPLOYEE_ID` as fallback |
| `workflows` | `function_app.py:225-226` | Pass user name to workflow |
| `flight-check` | `pages/api/netsuite/sync/syncpo.ts:61-64` | Add user identity to request body |

**Pull Requests:**

- `workflows` #31 (deploy first)
- `flight-check` #36 (deploy second)

**Rollback:**

Set `NETSUITE_EMPLOYEE_LOOKUP_ENABLED=false` in Azure Function App settings to revert to original behavior.
