# GP-288 — Navira dashboard prototype gap-closure (data-population lanes)

Home ticket for closing the remaining gap between the [[navira-marketing-dashboard|GEP InSite]] dashboard and the client prototype. Layout is already ≈1:1 (21/21 sections byte-faithful, 60-col table, metric-law bugs fixed); the remaining distance is **data population** — fill the honest Coming/Gated scaffold source-by-source — plus one UI feature. **Faithful population only** — never fabricate; unsourced fields stay honest "—"/Coming/Gated. **Status: Consulting/Design** (Sprint 7, assignee Paul, label `navira-roadmap`). ## Done

### Lane 1 — Campaign names verified + honest top-level Type (commit `f57e0c8`)
Probed `MARKETING_DIM_CAMPAIGN` (TEST) → `CAMPAIGN_ID, CAMPAIGN_KEY, CAMPAIGN_NAME` (no type column — corrected a spec contradiction). Name `LEFT JOIN` resolves **99% Amazon / 95.5% overall** (dim Amazon-only → Google/Meta keep the ID fallback). Type had been hardcoded `sponsored-products` for every campaign → now derived top-level from the name prefix (`SP/SB/SBV/SD`; **97.2% classify**, rest honest "—"). 399/399 vitest.

### Lane 2 — Platform-detail wiring: Google/Meta search-visibility + Meta video/reach (commits `698c310` + `015ce4b`)
Consumed `MARKETING_FCT_PLATFORM_DETAIL` (built but unwired). **413/413 vitest** (+14), tsc + lint clean.
- **Live-schema probe first:** the 16 assumed columns match; **`GOOGLE_ROAS` junk (max 0.12) and `GOOGLE_VIDEO_VIEWS` empty → skipped**; `AD_GROUP_ID` Google-null (grain = campaign×day, ad-groups Meta-only); impression-share ratios have no per-row impression weights → honest **unweighted mean of daily values** (never SUM a ratio).
- **Attribution decision (no fabrication):** the prototype's `top_of_search_impression_share`/`top_of_search_bid_adjustment` columns are tagged source = **Amazon Ads**, but this feed is **Google/Meta** — so the real metrics are surfaced as correctly-attributed `context` rows in the "Search visibility / win rates" section (Google) + a new Meta "Video & reach" section; the **Amazon-Ads columns stay "Coming"** (no source mislabeling).
- **Fixed a latent fabrication:** hardcoded `$0.00 daily budget` on every card → real avg daily budget for **124** Google campaigns, "—" otherwise.
- **Consumer-layer validated through the real provider path** (not synthetic): Google search-IS 27.1%, top-of-search 27.1%, abs-top 19.0%, budget-lost 3.5%, rank-lost 69.7%; Meta retention 66→32→20→13% across 83.6k video views.
- **Deploy prereq done:** granted `NAVIRA_MKT_RO` SELECT on the view (additive; rollback captured). Also fixed a pre-existing `ThemeToggle` lint break that was blocking `npm run lint` for the deploy gate.

## Remaining lanes (priority order)

1. **Traffic completion** (`TRAFFIC_FCT_ACTIVITY`) — buy-box %, sessions, units, CVR (detail-page-views already live). `getTraffic()` exists **and is already wired** → likely no new SQL. **← next solo lane.**
2. **"See all" expanded modals** — UI only, no data dependency. Full-screen drill overlays (All Campaigns / Keywords / Search Terms / Products). The one genuine un-built prototype UI feature.
3. **SmartScout integration** — biggest single visual unlock (brand market-share, ratings/reviews/BSR, ~45 gated columns, 3–4 scaffold sections per lens). **Client-gated:** needs confirmation a SmartScout feed is contracted/coming. Today all honest Gated.
4. **New-view SQL (evidence-gated):** portfolio grain, bid strategy / cost type / status / start-end dates, placement breakdown — all from **Amazon Ads raw** (NOT in `MARKETING_DIM_CAMPAIGN`, which has only ID/KEY/NAME).
5. **Campaign-level USD** — *blocked*: campaign `COST`/`SALES_AMOUNT` are native currency with no `CURRENCY_CODE` ([[transaction_currency_handling]]). Keep native-currency-labelled at campaign grain until rows are tagged with marketplace currency and consolidated.
