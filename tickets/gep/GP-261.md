# GP-261: Configure Navira Snowflake to ALDC for Ingestion

**Jira:** [GP-261](https://analyticlabsdc.atlassian.net/browse/GP-261)
**Status:** To Do
**Assignee:** Paul Russell
**Collaborator:** Justin Shuster (jshuster@navira.io)

## Summary

Define and configure an ingestion pipeline from Navira's Snowflake instance to ALDC. First Snowflake-to-Snowflake connector — all existing connectors are API → Python → Snowflake.

## Architecture Decision (2026-05-25)

Three options evaluated:

| Option | Approach | Verdict |
|---|---|---|
| A | Direct Data Share (Navira → ALDC) | Rejected — fragile, cross-region blocker, ALDC has documented 3 share failure modes |
| B | Direct Share + Local Materialization | Rejected — still depends on share, double complexity |
| **C** | **Prefect ETL Pipeline (pull-based)** | **Selected** — ALDC controls pipeline, loud failures, cross-region solved, fits existing connector architecture |

**Full analysis:** `C:\Users\PaulRussell\.claude\plans\whimsical-honking-clarke.md`

**Key reasons for rejecting shares:**
- Eclipse `CREATE OR REPLACE TABLE` silently drops share grants (4 incidents, April 2026)
- 42-day frozen share went undetected (Sellercloud staleness)
- Cross-database grant loss caused 14-hour production outage (May 2026)
- As consumer, ALDC would have even less control than as provider

**Key reasons for Prefect ETL:**
- Full ALDC control over the pipeline
- Failures are loud and recoverable (last-known-good data persists)
- Cross-region/cross-cloud handled implicitly (Navira's region unconfirmed)
- Fits existing connector pattern — just another Prefect flow
- Aligns with ongoing legacy connector → Prefect migration
- Easy to extend: Navira grants SELECT on new views, ALDC adds to flow config

## What Navira provides

1. Read-only Snowflake role + service account with key-pair auth
2. List of views to expose + expected schema
3. Preferred refresh frequency

## ALDC implementation

1. Store private key in Azure Key Vault (`gep--navira-snowflake--private-key`)
2. Create Prefect Snowflake block: `navira-snowflake-reader`
3. Build flow `navira-snowflake-ingest` in `prefect-connectors`
4. Target schema: `{ENV}_DG1_GEP.NAVIRA_INGEST`
5. `WAREHOUSE_SOURCE` views on top, feeding into existing warehouse pipeline
6. Deploy to non-prod (OG35375) first, then prod (WJ66376)
