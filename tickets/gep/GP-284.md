# GP-284 — Navira self-service order exclusion (client-maintained list)

Follow-on from [[GP-283]]. Navira was offered a self-service way to flag orders for exclusion (no support email + wait, no per-order engineering deploy). **Status: To Do — gated on Navira confirming they want it (offered 2026-06-18).**

## Goal
Let Navira maintain their own order-exclusion list with no code deploy per order.

## Design — graduate the static view to a CSV supplement
Swap the static `WAREHOUSE_SOURCE.SALES_DIM_ORDER_EXCLUSIONS` view (built in [[GP-283]]) for a `csv_v1` Eclipse supplement, mirroring the existing `MARKETPLACE_CONFIG` / `COMPANY_NAME` CSVs:
- New `excluded_orders` `csv_v1` connection + template (topic `SUPPLEMENT`) → `PROD_DG1_GEP.SUPPLEMENT.CURRENT_EXCLUDED_ORDERS_CSV` (shared to TEST via the prod→test share).
- Repoint the `NOT EXISTS` in `sales_dim_order_base.sql` from the static view to the CSV table — reference shape unchanged, low-risk swap.
- Client (or support) uploads/edits a CSV via the Eclipse portal; no code deploy per exclusion.

## Open questions
- **ID translation:** Navira sees the raw order number; the warehouse form is `'SC_' || SellerCloud ID` (or `'AMZ_' || Amazon ID`). Either accept the raw id and prefix in-view, or give the client the warehouse-form id.
- Columns: ORDER_ID, REASON, REQUESTED_BY, DATE_ADDED.
- Setup cost: standing up the `csv_v1` connector + a portal upload in PROD (heavier than the static view; justified only if exclusions recur).
