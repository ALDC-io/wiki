# GP-254 — Lectric eBike Agency Onboarding (multi-tenant sales)

**Type:** Story | **Roadmap:** [[phase-1c-sales-agency-customers|Phase 1C]] (Sales — Agency Customers) | **Assignee:** Paul Russell
**Branch:** `feature/paulrussell/gp-254/lectric-agency-onboarding` (clients repo)

First agency tenant onto the Navira DWH — proves the multi-tenant model: a second client's Amazon
sales land in an isolated schema, segmented by `ENTITY_CODE`, with zero cross-tenant leakage and
**no schema change** to the shared model.

> **✅ STATUS 2026-06-04 — Sample integrated + validated in the Sandbox marketing model.**
> - **Data model (sales side) built:** `WAREHOUSE_SOURCE.SALES_FCT_LECTRIC_AMAZON_ORDERLINE` (secure view) reads Lectric's **isolated `AMAZON_LECTRIC` schema** (`CURRENT_REPORT_ALL_ORDERS_{US,CA,MX,BR}`), stamps `ENTITY_CODE='LECTRIC'` as a literal (keyed off the landing schema — the all-orders report has no seller id; the `SHARED_DIM_ENTITY` CSV map is marketing-side only). Convention: schema `AMAZON_<ENTITY>`. Sales-only (no marketing — agency Amazon Ads not authorized).
> - **Deliberately separate from `SALES_FCT_AMAZON_ORDERLINE`:** the shared GEP fact is tightly coupled to Navira's Sellercloud product/brand/cost dims; Lectric's ASINs aren't in those dims (would yield NULL products/broken costs). Full dimensional integration is a follow-on phase; this view proves isolated landing + segmentation from the raw all-orders report alone.
> - **Integrated into the Sandbox efficiency model (2026-06-04):** materialized into `WAREHOUSE_TEST_GP226.SALES_FCT_LECTRIC_AMAZON_ORDERLINE` (real table, no cross-DB) + added a LECTRIC sales-only branch to `MARKETING_EFFICIENCY` (FX local→USD). Shows in the **`GP225 Marketing Validation`** report Page 4 (Multi-Tenant/Agency) via an `ENTITY_CODE` slicer. **DAX-validated:** LECTRIC **$568,533 sales / 744 units / 327 orders / MER blank** (sales, no spend = correct agency reality); NAVIRA numbers unchanged when sliced. See [[GP-225]].
> - **Data state:** only a **327-order test sample** is landed (US 147 / CA 90 / MX 60 / BR 30) in `TEST_DG1_GEP_DEV.AMAZON_LECTRIC`. **Full backfill PENDING.**

## Multi-tenant model (the reusable pattern)
- **Tenant key = `ENTITY_CODE`** on the unified marketing fact + every `MARKETING_EFFICIENCY` view; **`SHARED_DIM_ENTITY`** maps platform accounts → entity (the marketing-side isolation gate; INNER JOIN prevents foreign-account leakage).
- **Onboard a tenant = new `ENTITY_CODE` rows + a `SHARED_DIM_ENTITY` entry** — no new tables, no measure changes. Validated end-to-end with LECTRIC.
- **Agency = sales-only until ad access:** with no spend, MER is undefined; the tenant shows actual revenue. Tier-3 product-grounding needs a **per-entity product dim** (agency ASINs aren't in Navira's Sellercloud master). See [[cross-channel-marketing-attribution]].

The materialized shadow table + efficiency views auto-grow.
- **NEVER** run on the shared TEST agent — ~48 active templates feed the live Test model; a large backfill floods the queue (cf. the 2026-06-03 PROD incident). See [[project_test_eclipse_pick_bug]].
