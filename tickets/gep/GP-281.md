# GP-281 — Cost-value feed stall (2026-03-03) → TEST warehouse clone-staleness

Product cost values appeared frozen at 2026-03-03 in TEST COGS/margin. **Root cause was corrected on 2026-06-15**: it is NOT an upstream feed failure — it is TEST-environment clone staleness, and the fix is a warehouse change (in reach). Surfaced during [[GP-259]] / [[GP-PENDING-missing-cogs-cost-history]] Option A validation.

> **Contradiction (resolved 2026-06-15):** the ticket's original description + the GP-259 findings claimed "upstream ALDC Library cost integration died 2026-03-03; cross-repo fix; not the warehouse." That is **wrong**. The earlier diagnostic measured through TEST's cost-history view, which reads a **frozen clone**, not the live source.

## Corrected root cause (proven, 2026-06-15)
- The live PROD share `PROD_DG1_GEP.SELLERCLOUD_SQL.COMBINED_MAIN_PRODUCT` SITECOST/LANDEDCOST are **still changing** (Apr 973 / May 2,331 / Jun 774 distinct changes); max history ts current. The legacy Eclipse SellerCloud-SQL connector (`dbo.bvc_Product`, full SELECT-* pull, `clients/GEP/eclipse/templates/seller_cloud_sql/product.json`) is healthy.
- **The freeze is TEST clone staleness:** `TEST_DG1_GEP.SELLERCLOUD_SQL` (and AMAZON/SUPPLEMENT) raw tables are **March-2026 clones never repointed to the live share** when clone-only TEST was lifted ([[dwh-clone-only-deploy]] era). TEST's warehouse views (`SALES_FCT_COST_HISTORY`, `SHARED_DIM_PRODUCT_BASE`, …) read the frozen clones → TEST COGS carries stale March costs.
- The **canonical clients-repo warehouse SQL already reads `PROD_DG1_GEP.SELLERCLOUD_SQL.*` (the share, fully qualified) and handles `'$'`-money** (LTRIM/TRY_CAST). TEST has stale, clone-reading, pre-fix versions.

## Consumer impact (quantified, as-of CREATE_DATE)
Net COGS only **+0.065%** ($24k on $36.7M covered SC COGS) — immaterial at headline, but corrects ~2,063 products / ~51k lines at the SKU level. (post-03-03 net −$4,315; pre-03-03 restatement +$28,328 — live history is more complete than the clone.)

## Fix — broader alignment sweep (Paul's call, 2026-06-15)
Align the stale clone-reading TEST warehouse views to the canonical share-reading versions. Deploy as the views' **current owner** + `COPY GRANTS` (preserves ownership + SELECT=REPORT_SVC; see [[gep-snowflake-pbi-deployment]] grant rules). **Deployed as SYSADMIN** (2026-06-15) — the cost/dim views were SYSADMIN-owned, not CORE_SVC; SYSADMIN reads the share fine, and CORE_SVC can't `CREATE OR REPLACE` a SYSADMIN-owned object without an ownership transfer. (The boot prompt's CORE_SVC was a carryover from the abandoned raw-repoint approach.) Confirmed worklist after per-object freshness investigation:

- **ALIGN — 12 views:** `SALES_FCT_COST_HISTORY`, `SHARED_DIM_PRODUCT_BASE`, `SHARED_DIM_VENDOR/BRAND/WAREHOUSE/CURRENCY/DATE/COMPANY_CURRENCY_MAP/LOCATION`, `EXTRACT_FBA_MANAGE_INVENTORY`, `TRAFFIC_FCT_ACTIVITY`*, `SALES_FCT_BUDGET`. 8 shadow-validated clean against the share (incl. both COGS branches); cost-history advances 2026-03-03 → 2026-06-15.
- **DEFER (share OLDER than TEST = separate prod-side feed gap):** `PURCHASING_FCT_BALANCE` (`CURRENT_MAIN_PURCHASE` share=2025-07), `SHARED_DIM_CUSTOMER` (`CURRENT_ORDERS_HEADER` share=2024-08).
- **LEAVE (live in TEST):** `MARKETING_DIM_CAMPAIGN` (AMAZON_ADS landing live — Windsor/marketing).
- ***DEFERRED:** `TRAFFIC_FCT_ACTIVITY` — re-checked 2026-06-15: both share sources (`CURRENT_REPORT_SALES_AND_TRAFFIC_CHILD` **and** `_CA`) are present + fresh in the share, but they belong to the **same intermittently-dropping Amazon report family** as the orders ([[GP-PENDING-data-share-stability]]), so its live view would inherit that intermittency. Hold until the share-stability fix lands. Net deployed = **11 of the 12** files.
