# GP-258 — Incorporate Forecast in SKU Profitability Report

Add forecast data to the [[GEP]]/Navira SKU Profitability report. Jira (To Do, Medium, Paul): "Forecast data is already in NextCloud — was previously used on the old daily sales dashboard. Need to incorporate forecast data into the current SKU Profitability Report."

> **Status (2026-06-18): SCOPED, not built.** The forecast is already fully pipelined to **brand × date** grain. The crux is a **grain mismatch** (forecast has no SKU) + a client decision on presentation. See [[GP-156]] (the spec twin) and [[concept-gep-data]] (the app).

## The crux — grain mismatch

The forecast source has **no SKU/ASIN column**. End-to-end:

```
NextCloud CSV (/Client_Tenants/GLOBAL_ECOM_PARTNERS/CSV SUPPLEMENT/Forecast with Type)
  → Eclipse supplement "forecast_with_type"  → SUPPLEMENT.FORECAST_WITH_TYPE
       cols: DATE, TYPE, TYPE_NAME, GROSS_SALES, NET_SALES, QUANTITY, UPT  (grain = DATE × TYPE × TYPE_NAME)
  → WAREHOUSE.SALES_FCT_BUDGET            (grain = BRAND × DATE; BRAND_KEY = SHA2(brand);
                                           manufacturer rows pro-rated across brands)
  → REPORT_COMMON.RETAIL_DAILY_SALES_FACT (the "old daily sales dashboard" / DSR;
       "budget"→"Forecast" = GROSS_SALES, "forecast"→"Reforecast" = NET_SALES)
```

`TYPE` is `'Brand'` (TYPE_NAME = brand) or `'Manufacturer'` (forecast spread evenly across that manufacturer's brands — matches Heather's "Kent/Cepia spread across all brands" rule in [[GP-156]]). The SKU Profitability report is **SKU × date** (`RETAIL_SKU_PROFITABILITY_FACT`, `PRODUCT_KEY × DATE_KEY`). **A true per-SKU forecast does not exist in the source.**

Files (clients repo): `GEP/eclipse/connections/forecast_with_type.json`, `GEP/eclipse/templates/supplement/forecast_with_type.json`, `GEP/snowflake/warehouse/sales_fct_budget.sql`, `GEP/snowflake/report_common/RETAIL_DAILY_SALES_FACT.sql`, `GEP/reports/daily_sales.json`.
