# GP-217 — CI/CD Pipeline + Infrastructure Right-Sizing

Automate Docker build → GHCR push → Work Pool refresh per branch. Bundled with Prefect infrastructure right-sizing.

## Scope

- CI plumbing: quality gate must pass before Docker image publishes
- Infrastructure right-sizing: downsize overprovisioned Azure resources
- Do NOT change Work Pool env vars (GP-218) or migrate any connector (GP-219)

## CI/CD Pipeline (Done ✅)

### What changed

Consolidated `docker-publish.yml` into `ci.yml` so Docker builds only run after the quality gate passes (pytest, semgrep, trufflehog, architecture). Previously, `docker-publish.yml` ran independently — a broken merge could publish a bad image.

- **Branch:** `feature/paulrussell/gp-217/ci-cd-pipeline`
- **Commit:** `9223e2e` — `feat(gp-217): gate Docker publish behind quality gate`
- **Tag mapping:** `main` → `:main`, `uat` → `:uat`, `development` → `:development` (no `:latest`)
- **SHA tags:** Each build also tags with short SHA for rollback pinning
- **GHCR auth:** `github.actor` + `GITHUB_TOKEN` (built-in, no personal PAT)
- **Prefect block:** `ghcr-io-aldc-io` already updated to `russell94paul` (2026-05-01)

### Why no explicit Prefect refresh

ACI Work Pools create ephemeral containers per flow run — each run pulls the tag from `job_variables.image`. No stale cache. Next scheduled run uses the updated image automatically.

### Lead time

PR merge → ~3-4 min CI → GHCR updated → next flow run picks up new image.

## Infrastructure Right-Sizing (Done ✅)

### Pre-flight: VNET check

App Service **does** use VNET integration (subnet `prefect-app-service` in `aldcprodvnetconnector1c`). PostgreSQL has `publicNetworkAccess: Disabled`. B2 not viable — S1 is the minimum.

Verified both resources are single-tenant before downsizing:
- App Service Plan: only `aldcprodwbapprefectserver1c01`
- PostgreSQL: only `prefect` database (plus system DBs)

### Known issue: Claude review gate vs workflow changes

`claude-code-action` OIDC token exchange fails with 401 when `ci.yml` on the PR branch differs from the version on `main` (default branch). Error: "Workflow file must exist and have identical content to the version on the repository's default branch."

**Impact:** Claude review gate will fail on any PR until the `ci.yml` change is promoted to `main`. Push events (merges) are unaffected — Claude review only runs on PRs.

**Fix options:**
1. Promote workflow changes to `main` first (fast-forward merge or direct push)
2. Make the enforce gate tolerate action-level crashes (only block on `has_blockers: true`, not on OIDC/infrastructure failures)
