## The margin answer — no, and folding it in is Heather's call

`Actual - Margin - Net BASE` subtracts exactly one advertising term, which resolves to
`SUM('Order Line'[*_ADVERTISING_FEE_CONSOLIDATED])` — sourced from `WAREHOUSE.SALES_FCT_COST`.
That view reads **exactly two ad tables**: the Sponsored Products advertised-product report and
the Sponsored Brands campaign report. So net margin accounts for **Amazon SP + SB allocated fees
and nothing else**. Excluded: Google, Meta, Sponsored Display, and Amazon UK.

## ⭐ Four findings that changed the engineering picture

**1. The UK gap is not the marketplace filter.** `sales_fct_cost.sql` already admits UK —
`WHERE MARKETPLACE_NAME ilike '%amazon%'`. The gap is that the two ad-report tables it joins to
carry no UK rows. **"Widen the marketplace filter" is not the change.** Sponsored Display is absent
for a third reason again: no SD table is referenced by the view at all. Three superficially similar
absences, three different fixes — this is the "never inherit a target" rule
applied to a *view* rather than a consumer.

**2. A two-instrument gap that decomposes to zero residual.** Cost path vs marketing path, same
run, same axis, inside one environment (which the ticket's acceptance criteria require, because
cross-environment arithmetic is not sound):

| Marketplace | Marketing | Cost path | Gap | = SD scope gap | + allocation loss | Landing |
|---|---|---|---|---|---|---|
| Amazon US | 2,623,949.12 | 2,611,723.02 | 12,226.10 | 6,485.14 | 5,740.96 | 99.7807 % |
| Amazon CA | 59,044.26 | 59,009.77 | 34.49 | 0.17 | 34.32 | 99.9419 % |

Both exact. The 99.78 % landing ratio independently re-derives [[GP-322]]'s 99.81 %. ⭐ **A gap
that splits cleanly into named causes with nothing left over is much stronger evidence than a gap
that merely looks small** — and it corrected an inherited "$8,855.73 unexplained" note that had
conflated a *scope* gap with an *allocation* loss.

**3. A figure that moves between measurements is a time series, not a discrepancy — check
`LastProcessed`.** Amazon UK read $6,617.31 → $6,627.38 (01:21Z) → $6,633.04 (05:29Z), with model
`LastProcessed` 02:11:52Z sitting between the last two. Monotonic across three model states. The
same drift affects Google ($234,816.66 → $235,566.30) and Meta ($16,652.00 → $16,670.69); SD is
unchanged. ⇒ **Every figure quoted to a client must carry its measurement timestamp**, and a
"divergence" between two of your own runs deserves a `LastProcessed` check before it is written up
as a defect.

**4. Feasibility is testable at the model layer without a warehouse credential.** The cost view
joins on date × currency × ASIN, so the widening is only possible if UK spend exists at *product*
grain in *local* currency. Probed: **1,217 UK rows, 100 % resolving to a `PRODUCT_KEY`, carrying
GBP 4,984.76 alongside the USD** — better resolved than US (99.98 %). The model reads
`*_ADVERTISING_FEE_CONSOLIDATED`, so a GBP widening is FX-consolidated downstream; no new FX work.

Also: **UK Sponsored Display is NOT-RECORDED, not ZERO** — told apart by reading the unguarded
column (407 rows, `raw_sd` = exact `0.0`). That is what makes the overlap genuinely $0.00. The
technique is written up on [[answerability-guard]].

## What is deployed

**TEST `66151728`, commit `0da4811`:** `Sales Measures[Amazon Ad Spend (USD)]` = `[Amazon
Advertising Fees (settlement)]`, visible in `Cost & Margin`, money-formatted, with a 533-char
description carrying the basis and both exclusions.

⭐ **A pure alias was the safest possible additive measure.** Referencing the guarded source
measure meant the new measure inherited both the answerability guard and the exact-zero blanking
for free, cannot drift from its source, and introduced **zero new arithmetic** — which is why the
no-regression proof came out total rather than approximate.

Validation PASS on six gates: additive-only (exactly one measure added), no regression (all 13
headline measures byte-identical), consumer layer (US $2,611,723.02, CA $59,009.77, UK blank),
answerability (blank on the `Platform` axis — PROD leaks the grand total there), metadata, and
both bound reports still bound. **Rollback drilled, not merely captured:** apply → validate →
rollback → verified identical to baseline → re-apply → validate.

Scope delivered: **Amazon US + CA only.**

## Environment differences that bite

* **`Actual - Cost - Advertising` does not exist in TEST** — that name is PROD-only; TEST already
  carries the renamed, zero-guarded `Amazon Advertising Fees (settlement)`. Any instruction to
  "keep the old name as a hidden alias" is a no-op in TEST and only becomes live at PROD promotion.

## Security — the leak this ticket surfaced

"Capture rollback" *is* a TMSL export, and the export path was writing a live
`CORE_API_CLIENT_TOKEN` into git. ⭐ **The root cause was a BYPASSED control, not a missing one:**
`pbi_ops/.gitignore` had excluded `*.tmsl.json` since 2026-06-26, but **gitignore never affects
already-tracked files** — four of the six predate the rule and two were force-added after it. The
rule *looked* like coverage and did nothing.

⭐ **One credential value, authenticating against BOTH `aldctestfnapcore1c01` and
`aldcprodfnapcore1c01`** — not a test-only secret. 9 tracked files, 10 commits, all pushed, oldest
2026-06-04. Fixed with a shared fail-closed redactor in `pbi_ops/xmla.py` (11 call sites rewired),
commit `a3282e0`. **Rotation is still outstanding and is a human action** — everything else is
cosmetic until it happens.

## Gotchas earned

1. ⛔ **Never replay a full-model TMSL as a rollback on a concurrently-worked model.** It is a
   snapshot; replaying it silently reverts everyone else's later work. Use a surgical rollback.
2. **Recapture the baseline immediately before applying**, not at session start — this model moved
   358→369 measures and 40→41 tables inside one session.
3. **After deploying, verify the other person's objects explicitly** — table present, measure list
   identical, columns identical, their measures still *evaluate*, relationship count unchanged.
   Structural "additive-only" does not by itself prove their work still works.
4. **Assert the model ID, never resolve by name alone** — `GEP Test Models` holds more than one
   database.
5. **Jira's markdown→ADF conversion silently drops a leading blockquote** — a correction banner
   vanished on first edit. Re-read any description you edit.
6. Bash heredocs mangle backslashes and nested quotes — use Write/Edit for DAX money formats
   (`\$#,0.00`), and pass long commit messages via `-F <file>`.
