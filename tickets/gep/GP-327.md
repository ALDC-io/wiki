# GP-327 — remove the two MAP-only filters from the client vendor dashboards

**DEPLOYED to PROD 2026-08-26.** Cosmos-layer verified. Rendered-layer check still outstanding.

Client request (Navira, Heather Tabor, 2026-08-26): *"all brands that I had requested look good.
But what are these filters? Can we remove them?"* — screenshot highlighting **Selling FBA** and
**Min Avg ASINs Listed** on the Condor dashboard.

## What they were

Dashboard-level `filters[]` entries in PROD Cosmos, added by [[GP-310]] to preserve parity when the
19 dedicated `MAP Violators — <brand>` dashboards were retired and the MAP component was embedded
into the vendor dashboards instead. Not a defect — a control the client did not want.

| Display | Field |
|---|---|
| Selling FBA | `'Navira MAP Violators'[Selling FBA (Yes/No)]` |
| Min Avg ASINs Listed | `'Navira MAP Violators'[Avg ASINs Listed]` |

## ⭐ The reusable lesson — inert filter vs scoping filter

**An Eclipse dashboard filter with an empty `value` in BOTH `locked_value` and `default_value` is
inert: it scopes nothing until a user touches it.** Deleting one is a UI change, not a data change.
A filter with a real value in either is a *data* change wearing a UI change's clothes — deleting it
silently widens what the consumer sees.

So the gate before removing any filter is: read the live doc and check both fields. The removal
script here **aborts the entire run** if it finds a real value, rather than trusting the author to
have looked.

**The second instrument is free:** the rendered filter bar shows `<Any>` for an inert filter. The
client's own screenshot was therefore independent corroboration of the Cosmos read — two instruments
agreeing before touching prod.

## Scope gotcha

8 vendor dashboards were expected; **only 7 carried the filters**. Rain Bird (`645c8321`) had
already lost them to a later doc replacement (its `_ts` was ~12 days newer). It still rendered MAP
fine, which made it a **live control for the post-change shape** — worth looking for that kind of
accidental control before deploying.
