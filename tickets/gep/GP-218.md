# GP-218 — QA/UAT/Prod Work Pools & Promotion Pipeline

**Status:** In Progress (infra complete, PR #1 open for `short_code` fix, GEP E2E verification pending)

## Summary

Split the single `azure-aci-production` Work Pool into 3 environment-specific pools (QA, UAT, Prod), each with dedicated worker Container Apps, environment-specific env vars, and branch-mapped Docker image tags. Established the promotion pipeline: feature → development (QA) → uat (UAT) → main (Prod).

## Key Decisions

| Decision | Choice | Rationale |
|---|---|---|
| 3 pools vs 1 pool with overrides | 3 separate pools | Clearer blast radius — bad QA image can't affect prod |
| Separate vs shared workers | Separate Container Apps (Option A) | Isolation: independent scaling, independent restarts, a stuck run in one tier doesn't block others. ~$25/month extra. |
| `short_code` approach | Temporary `"GEP_PREFECT"`, flip to `"GEP"` at cutover | Avoids touching the framework's `warehouse_database_name` formula; change is scoped to the account file |
