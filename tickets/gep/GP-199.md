# GP-199 — ASIN Brand Campaign Attribution

**Type:** Scope | **Status:** Implementing — connector fix deployed, Eclipse merge failure under investigation | **Priority:** Top (Lori, 2026-04-28)

## Problem

Sponsored Brands campaign spend is attributed with `PRODUCT_ID = '-1'` in `marketing_fct_activity.sql`. Downstream, spend is distributed evenly across ALL ASINs in a brand via portfolio lookup. A campaign targeting 3 ASINs has its cost diluted across 50+ products, making per-product profitability inaccurate.

Sponsored Products already has accurate per-ASIN attribution via `ADVERTISEDSKU` in the Advertised Product Report.

## Key Research Findings

1. **Amazon does not provide per-ASIN spend reporting for Sponsored Brands** — confirmed API limitation because a single SB ad can feature multiple ASINs. No `sbAdvertisedProduct` report type exists (unlike `spAdvertisedProduct` for SP).

2. **Two data sources enable attribution:**
   - **Ad Metadata API** (`/sb/v4/ads/list`) — returns `creative.asins` per ad (targeting data). Connector does NOT support this yet.
   - **Purchased Product Report** (`sbPurchasedProduct`) — returns `purchasedAsin` per campaign (conversion data). Connector already supports this.

3. **SB Ads Report** (`sbAds`, category `ad_report`) — provides daily metrics per `adId` (impressions, clicks, cost). Connector already supports this but no Eclipse template exists for GEP.

4. The Eclipse `amazon_ads_v1` connector already supports SB categories: `campaign`, `campaign_report`, `ad_report`, `purchased_product_report`. Only `campaign` and `campaign_report` have GEP templates today.

## Approved Design (Justin Shuster, 2026-05-01)

**Approach A (Ad Creative Attribution)** — confirmed via email 2026-05-01.

### Allocation Formula (Confirmed)

Three-step model:

**Step 1 — Ad to ASINs (equal split):**
Split the ad's daily spend equally across all ASINs in that ad's creative.
> Example: Ad has 3 ASINs, $90 spend that day → $30 per ASIN

**Step 2 — ASIN to Orders (unit-ratio weighted):**
Distribute each ASIN's allocated spend across its individual orders that day, weighted by units.
> Example: ASIN-A allocated $30, had two orders (8 units and 2 units) → $24 and $6

**Step 3 — No sales (UNK bucket):**
If an ASIN in the ad had zero orders that day, it keeps its equal share as unattributed spend.
> Example: ASIN-C allocated $30, zero orders → $30 recorded as UNK spend

Justin explicitly confirmed: "do not weigh the initial split... evenly distribute across ASINs first."

### Historical Data (Confirmed)

**Option A — no backfill.** Existing SB data stays as-is (brand-level split). New ASIN-level logic applies from the go-live date — the date we start capturing daily ad-ASIN snapshots. Justin: "good with a backfill from 'go live' or whenever you start capturing the relationship between date => Ad => ASINs."

### Non-ASIN SB Ads Fallback

SB ads with no ASIN attribution at all (e.g., Store Spotlight, Video) continue current behavior: split evenly across the brand. Justin questions whether this case exists — verify during implementation.

### Daily Snapshot Requirement

Each day's ad-to-ASIN composition must be captured so that future ad changes don't retroactively alter past attribution. Justin: "if an ad changes in a month, it should not change what was being advertised today."

## Current State (marketing_fct_activity.sql)

- **Sponsored Products:** Uses `CURRENT_SPONSORED_PRODUCTS_ADVERTISED_PRODUCT_REPORT`, `PRODUCT_ID = ADVERTISEDSKU`, `AD_GROUP_ID` populated
- **Sponsored Brands:** Uses `CURRENT_SPONSORED_BRANDS_CAMPAIGN_REPORT`, `PRODUCT_ID = '-1'`, `AD_GROUP_ID = 'Unknown'`

## Schema Changes

**New raw tables** (auto-created by Eclipse):
- `AMAZON_ADS.CURRENT_SPONSORED_BRANDS_AD` — ad metadata with `creative.asins`
- `AMAZON_ADS.CURRENT_SPONSORED_BRANDS_AD_REPORT` — daily metrics per adId

**New warehouse views:**
- `WAREHOUSE_SOURCE.EXTRACT_AMAZON_ADS_SB_AD_ASIN_MAP` — flattened ad-to-ASIN mapping via `LATERAL FLATTEN` on `creative.asins`. Must preserve daily snapshots (not just latest).
- `WAREHOUSE_SOURCE.EXTRACT_AMAZON_ADS_SB_AD_DAILY_SPEND` — daily ad-level spend from `AD_REPORT`, joined to ASIN map for that date

**Updated view:**
- `marketing_fct_activity.sql` SB section: replace campaign-level query with ad-level query joined to ASIN map. Implement three-step allocation (equal split → unit-ratio → UNK).

**UNK handling:** Design needed — either:
- A synthetic `PRODUCT_ID = 'UNK'` row in `marketing_fct_activity` for spend on ASINs with no matching sales
- Or a separate unattributed-spend bucket that downstream PBI reports can surface

## 2026-05-20 Debugging Session

### Connector MIME type fix (resolved)

`SPONSORED_BRANDS_AD` had 0 rows since table creation (2026-05-06). Root cause: the `"ad"` category handler in `amazon_ads.py` used the wrong `Accept`/`Content-Type` MIME type:
- **Was:** `application/vnd.sbad.v4+json`
- **Correct:** `application/vnd.sbadresource.v4+json` (matching the `sbcampaignresource` pattern on the campaigns endpoint)

Secondary fix: omit `nextToken` from the POST body when `None` (API spec says omit, not send null).
