# GP-282 — Amazon UK order lines double-counted (SALES_DIM_ORDER_BASE UK branch missing anti-join)

A UK Amazon order that is also in SellerCloud appears in BOTH the SellerCloud (`SC_`) and Amazon-report (`AMZ_`) branches of the order-line fact → double-counted. Pre-existing (introduced with [[GP-200]]); surfaced during [[GP-259]] Option A validation.

## Root cause
In `WAREHOUSE_SOURCE.SALES_DIM_ORDER_BASE`, the **US** Amazon branch anti-joins SellerCloud (`LEFT JOIN (SellerCloud orders with ≥1 line) ORDER_LIMIT … WHERE ORDER_LIMIT.ORDERSOURCEORDERID IS NULL` — "Amazon preferred unless the order and a line are both in SellerCloud"). The **UK** branch (GP-200) has **no equivalent anti-join** → UK orders present in both sources emit twice.

## Impact (measured, TEST, 2026-06-12)
1,125 Amazon order IDs in both branches → **1,154 fact lines / ~$137K gross (0.11% of ~$120M total)**. Small, bounded, real. Slightly inflates COGS once GP-259 Option A backfills the SC copies.

## Fix
Extend the US anti-join pattern to the UK branch in `SALES_DIM_ORDER_BASE` (mirror `ORDER_LIMIT … IS NULL`). Evidence-gated: capture rollback; shadow-validate UK orders appear in exactly one branch; total gross/lines drop by the dedup amount; **US branch byte-identical (no regression)**. Deploy as `TEST_DG1_ROLE_CORE_SVC_DA8904DB` + `COPY GRANTS`; rebuild dim/fact; validate at PBI/DAX. Residual to confirm: pin whether the 1,154 are purely UK vs include US zero-order-line edge cases (one query).
