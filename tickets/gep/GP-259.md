## Return logic EXISTS (CCE correction)

CCE concluded return-adjusted Net/COGS "was never built" and proposed building it in a dbt gold layer. **That is wrong on all counts.** The return logic is live in `WAREHOUSE.SALES_FCT_ORDERLINE` (`_gp259_fct_orderline_src.sql`):

- **Net = Gross − Refunds** (`:199-205`)
- **COGS qty = gross − returns** (FBA: `gross − sellable_returns`, so damaged/defective returns still cost) (`:238-244`)
- **Return label fee** subtracted from margin (`:304-305, :324`; sourced from Amazon `LABEL_COST` `:429`)
- Returns sourced from Amazon reports `CURRENT_REPORT_RETURN` (MFN) + `CURRENT_REPORT_FBA_RETURN` (FBA disposition), `COALESCE`'d over SellerCloud (`:402, :651-712`)

Why CCE couldn't see it: it only has Zeus Memory — no access to the (local/uncommitted) warehouse SQL and cannot introspect a deployed Snowflake secure view. The logic is in the **warehouse transformation layer**, not DAX and not dbt (GEP's warehouse does not use dbt). No return-adjusted DAX measure is needed because Net/COGS arrive pre-adjusted.
