## The two fixes

### Fix A — work_pick connection scoping (`route_work.py`, commit `85557db`, GP-199 enabler)
`remove_non_active_connections` compared `connection_size.connection_id == connection.get("id")`, but agent `connection_authorized` entries key on `connection_id` (no `id`), so `.get("id")` was always None. Any zero-size connection with a null connection_id in the account-wide `work_size()` matched that None and dropped **every** scoped connection → `work_pick_agent` returned "no work items remaining" → connection-scoped agents could never pick queued work in TEST. Fix: match on `connection_id` (fallback `id`), ignore null ids. **Zero warehouse-table impact** (pure dispatch). **Validated server-side on stage** (GP-199 SB pull picked + ran). See [[project_test_eclipse_pick_bug]].

### Fix B — dtype-tolerant schema versioning (`route_warehouse.py`, commit `ee5b553`, GP-277)
`warehouse_schema_match` forked a new versioned table (`{table}_N`) on ANY non-exact schema match — including pandas per-partition dtype drift (bigint/float/varchar/object). One backfill produced 24 Google tables differing only in dtype labels. Fix: dtype-tolerant match — same column-NAME set + primary key routes to the existing table and reconciles dtypes by **widening** on `boolean<bigint<float<varchar` (atomic rebuild+SWAP), forking only on genuine column add/remove; **falls back to forking on any failure** (status-quo-safe). Helpers: `widen_dw_dtype`, `schema_name_key`, `reconcile_schema`, `warehouse_schema_all`, `_coerce_session_schema`, `warehouse_widen_target`, `warehouse_schema_match_tolerant`.

**Operates on RAW landing tables only** (topic schemas: `AMAZON_ADS`, `GOOGLE_ADS`, `META`, …). **Does NOT write to the `WAREHOUSE` schema** (built by separate client transformation SQL). Indirect downstream effect possible: a widened raw column (e.g. all-NULL day → varchar) flows into WAREHOUSE transformations / PBI → that's the consumer-validation gate.

**Validated 34/34** (logic + real Snowflake mechanics, NOT deployed-merge-path):
- `warehouse_ops/_gp277_fix2_validate.py` 17/17 — lattice, replay of the 24 real Navira Google versions (collapse to 1, converges in 4 widen events), add/remove forks, live rebuild+SWAP.
- `warehouse_ops/_gp277_fix2_validate_ext.py` 17/17 — multi-column widen, metadata (`___ALDC___*`) + PK preservation, values intact, convergence, **safe fork-fallback** (bad cast raises → original table intact, never SWAPped).

## Fix C — `session_id` arg bug in Fix B (2026-06-03 pm-2, commit `b1cc08c`) — merge path now PROVEN

Exercising the merge path for the first time (Navira canonical Google land) returned **500 "route function not currently implemented"** from `/warehouse/merge`. Root cause: `route_warehouse.py:1061` called the new `warehouse_schema_match_tolerant()` with **7 positional args, omitting `session_id`** (the function requires 8) → `TypeError` on **every fresh-version creation** (the `else` branch hit by the first partition of any topic). The catch-all handler at `v1/__init__.py:1035-1056` reuses one generic 500 message for **all** unhandled exceptions and its `traceback.format_exc()` captures the *handler's* `json.loads(str(e))` failure (`JSONDecodeError: Expecting value: line 1 column 1`), not the real error — so the real `TypeError` is **masked**. (Gotcha now recorded on [[core_api]].)

- **Fix:** one line — inserted `session_id` as the 2nd arg. Compile-checked; deployed `func publish --slot stage` → smoke → `az functionapp deployment slot swap` stage→production (`aldctestfnapcore1c01`) → prod-slot smoke clean.
- **Proof at consumer layer:** Navira Google `2024-01-01` partition landed **4 rows** into `TEST_DG1_GEP.GOOGLE_ADS.GOOGLE_ADS_CAMPAIGN` at **clean v1 (version 0, base table — NO `_N` fork)** with `CURRENT_`/`COMBINED_` views auto-built. This validates Fix B's single-version behaviour **and** dtype-pinning end-to-end — the long-standing "merge path unexercised" residual is **closed**, and this is the "confirmed working" evidence Paul wanted before merging the branch.
- **Why merge worked before but not now:** pre-swap TEST ran the old code (no tolerant call); the swap put the branch's Fix B live, and its first fresh-version creation tripped the bug.
