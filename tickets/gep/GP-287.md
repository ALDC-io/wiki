# GP-287 — Amazon Attribution feed (Google/Meta → verified Amazon orders)

Attribute Amazon marketplace sales **driven by external Google/Meta ads** back to those channels — the "Amazon-destination" ad spend that today has no measurable sales in the [[navira-marketing-dashboard]] / marketing model. Amazon Attribution is the purpose-built feed: external ad click → **verified Amazon order** (new-to-brand purchases/sales, long-term sales/ROAS). It is the *measured* path that the [[cross-channel-marketing-attribution|Tiered Measurement Model]] otherwise leaves as "spend-only" for the Amazon destination. **Status: In Progress** (Sprint 7 / S7, ALDC board; assignee Paul; label `navira-roadmap`). **Connector + Eclipse feed LIVE in TEST and canary-validated 2026-07-15** — remaining = warehouse view → full backfill → dashboard wiring → durable daily refresh.

## Investigation (2026-07-15, read-only Windsor probes)
- **Enrollment: confirmed.** Navira is Brand-Registered (we already ingest Sponsored Brands) → Amazon Attribution is available. No enrollment blocker.
- **Tagging (Google): LIVE via Quartile.** Landing URLs carry the canonical Attribution tag `?maas=…&ref_=aa_maas&tag=maas`. Verified from the [[Windsor]] `final_url` field.
- **Coverage (Google, 90d): 93% of Amazon-bound Google spend is tagged** — $37,836 of $40,682 (total Google $55,538). Untagged residual ≈ $2,846 (Slobproof PMax — not Quartile-managed — + a few small keyword campaigns).
- **Meta: N/A.** $5,969/30d (Brinno + Cibu), 0 Amazon-bound (all Websites/M2W) → nothing to attribute; leave as-is.
- **Key technical finding:** `final_url` is available from Windsor but **not currently pulled** (connector template uses a curated `fields` list) — a field-selection gap, not an API-access gap. The Amazon Attribution *report* is a separate `amazon_ads` connector product (reuses the Amazon LWA OAuth), not yet built.

## Build + canary — LIVE in TEST (2026-07-15)
The `attribution` product was built, deployed, and **canary-validated end-to-end** — real Amazon Attribution data landing in TEST. This was the FIRST direct call to the Amazon Attribution API (the earlier feasibility used Windsor only).
- **Connector** `feature/amazon-attribution-connector` (connector repo): `41d5bd6` (ATTRIBUTION product — distinct `/attribution/*` cursor-paginated API, per-profile `advertisers`→`report`) → `7863823` + **`2fa0cb0`** (two live-API bugfixes, below). Image `ghcr.io/aldc-io/agent-dcgeneral:attribution`.
- **Eclipse feed** deployed to TEST Cosmos via `aldc-launchpad/warehouse_ops/_deploy_attribution_cosmos_test.py`: scoped connection `0556a280…` (copies OAuth from shared `amazon_ads` conn `66627ed9`; `max_connection:2`), template `8331ca49…` (topic AMAZON_ADS, active), scoped agent `gep-amazon-attribution-test` (runs on wks-agent). Landed `TEST_DG1_GEP.AMAZON_ADS.ATTRIBUTION_PERFORMANCE_REPORT` (+ `CURRENT_…` view).
- **Two connector bugs found + fixed via the canary:** (1) `get_attribution_advertisers` raised on any 4xx (helper `RestSimple.Transact()` raises on non-200) → GEP's **BR profile 403 "not authorized to use Amazon Attribution"** aborted every partition; now caught in `except` → skip profile. (2) `ATTRIBUTION_PERFORMANCE_METRICS` included `attributedNewToBrand*` which PERFORMANCE rejects (HTTP 400 "Invalid metric") → removed (NTB may be PRODUCTS-only).
- **Scoping determined by EVIDENCE (not advertiser name):** the shared `amazon_ads` conn serves multiple GEP clients (advertisers GlobalEcom / The Super Savers / Falls River Soap). Scope = Navira's `profile_id`s per `marketing_fct_activity.sql` MARKETPLACE_PROFILE_MAP (US `2874274850477920` / CA `410071870980733` / MX `1359269695432602` / BR `2944710254877284`). Only the **US** profile carries attribution data (CA/MX = 0 rows; BR 403). Its rows show advertiserName both 'The Super Savers' + 'GlobalEcom' (both GEP/Navira brands). Live 30d probe: publisher 'Google Adwords' → **$4,644 attributedSales14d** (single canary day = $0 is normal; attribution is sparse day-to-day).
- **Landed shape confirmed** (drives the view): UPPERCASE VARCHAR cols incl. `ATTRIBUTEDSALES14D`, `PUBLISHER`, `PROFILE_ID`, `CLICK_THROUGHS` (hyphen→underscore); **no NTB columns**; `DATE` = `'YYYYMMDD'`; publisher values `Google Adwords/Google Display Network/Youtube/GlobalPR/'1'` → map Youtube→GOOGLE, exclude GlobalPR/'1'.

## Plan / path forward
- **Core — Amazon Attribution report (the revenue):** add an `attribution` product to the `amazon_ads` connector (reuses existing LWA OAuth) → pull new-to-brand purchases/sales + long-term sales/ROAS, keyed by campaign/tag → land `{ENV}_DG1_GEP.AMAZON_ADS.CURRENT_ATTRIBUTION_*` → warehouse join → surface as Amazon-destination attributed sales in `MARKETING_EFFICIENCY` + the dashboard's Amazon-destination cells (which show "attribution pending tagging" today).
- **Optional — `final_url` from Windsor (QA + ASIN grain):** add `final_url` to the Google Windsor connector `fields` to cross-check tagging + extract target ASIN (`/dp/…`) for product-level attribution. Not required for the revenue number.
- **Meta:** out of scope (no Amazon-destination spend).
