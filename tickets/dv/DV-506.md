# DV-506: Eclipse invitation emails not received by external user (brinno.com)

## Status: Proposed — to be discussed in future planning session

## Summary

GEP/Navira brand partner Terence (terence@brinno.com) has not received Eclipse invitation emails despite 5+ sends by Heather Tabor. No UI errors were shown — Mailjet API appears to return success but emails never arrive.

## Root Cause Analysis

**Likely:** Email deliverability — Mailjet transactional emails from `mailjet@aldc.io` filtered/blocked by brinno.com's mail server (SPF/DKIM/DMARC filtering, spam gateway, or domain reputation).

**Not related to:** ALDC Email MCP Server secret expiry (2026-05-25, tracked in [[GP-PENDING-infra-connector-failures]]) — that's Microsoft Graph, not Mailjet.

**Precedent:** [[DV-194]] — same pattern (password reset email not received).

## Investigation Details

### Invitation flow (core_api)
1. Admin sends invite → `POST accounts/{accountId}/memberInvites/`
2. Backend creates invite in Cosmos DB (UUID code, 7-day expiry)
3. Mailjet API sends HTML email from `mailjet@aldc.io` → `terence@brinno.com`
4. If Mailjet returns >= 300, backend raises HTTP 500 — but no error was shown to Heather

### Code references
- `core_api/api/accounts/router.py:100-120` — invite creation
- `core_api/api/member_invites/lib.py` — email template + send
- `core_api/api/email_utils.py:124-141` — Mailjet send function
- `core_api/api/member_invites/router.py:13-32` — invite code validation (7-day expiry)

### Key observations
- Mailjet uses static API keys (no token expiry risk)
- No delivery status tracking — Mailjet returns 200 but ALDC has no visibility into bounces/spam classification
- No fallback when email fails silently
- Invite link format: `{origin}/signUp?code={inviteCode}` — the link exists, just not surfaced in the UI

Direct signup link retrieved from Cosmos DB and shared with client (valid until 2026-05-28):
`https://eclipse.analyticlabs.io/signUp?code=d2aadc8fc23b488fb4ce53d93a1550be`

3 invites found in Cosmos DB — 2 expired (2026-04-20, 2026-05-15), 1 valid (2026-05-21). API verified 200 on valid code.

## Proposed Fix (Two Phases, pending approval)

### Phase 1 — Copy Invite Link (Lori asked to prioritize in future planning session — not yet approved for development)
When an admin sends an invitation, they'll also see a **"Copy Link"** button next to each invite. If the recipient says they didn't get the email, the admin can copy the signup link and share it directly — by Slack, text, or their own email. No need to contact ALDC support. Self-service resolvable by the client admin.

### Phase 2 — Email Delivery Tracking (proposed, pending scheduling)
- **Mailjet Event Webhooks:** receive delivery events (delivered, bounced, spam) via Azure Function callback
- **UI status indicator:** show delivery status next to each invite — "Delivered", "Bounced", "Spam"
- **Auto-fallback prompt:** if email bounces, surface toast: "Email delivery failed — copy the invite link to share directly"
- **Sender domain fix:** change from `mailjet@aldc.io` to `support@aldc.io`, verify SPF/DKIM/DMARC records
