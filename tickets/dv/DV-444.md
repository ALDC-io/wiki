# DV-444 — Rename Navira-Demo Sidebar App to "SKU Profitability"

Rename the sidebar **Apps** group entry that GEP/Navira users see from **"Dashboard"** to **"SKU Profitability"** so it is distinguishable from the generic "Dashboards" nav link. Affects [[GEP]]/Navira and all downstream customers the app is shared with.

## Jira

- Link: https://analyticlabsdc.atlassian.net/browse/DV-444
- Context: GEP/Navira request. The iframe's own internal title is already "SKU Profitability Dashboard"; the sidebar label was generically "Dashboard", which clashed visually with the top-level "Dashboards" nav link.

## Scope discovery (2026-04-21)

Initial ticket framing: *"code change to eclipse-2.1."* After investigation, that framing is wrong:

- The sidebar entry lives in the Navbar's **Apps** group (`eclipse/src/components/Navbar/Navbar.tsx:108-120`), which renders `app.appName` for each record returned by `GET /v2/applications/hierarchy`.
- URL signature in the running UI: `http://localhost:3000/application/navira-demo` — confirms the item is an **Application** record (iframe-app surface), not a dashboard or explorer tab.
- The label source is therefore **data in CosmosDB**, not code in the eclipse repo. The feature branch `feature/paulrussell/dv-444/change-display-name-of-dashboard` will close with zero commits.

## Decision — execution path

Three options surfaced during discovery. Chose **Option C: direct CosmosDB patch via Azure Portal Data Explorer**.

| Option | Status | Rationale |
|---|---|---|
| A. Uncomment the legacy `/v1/` router in `core_api/api/main.py:164` | ❌ | Exposes every legacy v1 endpoint, not just the one we need. Unbounded surface risk for a one-line fix. |
| B. Add a v2 PATCH endpoint on `core_api/api/applications/router.py` | ⏩ Deferred | Cleanest long-term, but expands DV-444 scope to a core_api PR + deploy. Tracked separately in [[action-items]]. |
| **C. Direct CosmosDB patch via Data Explorer UI** | ✅ Chosen | Smallest blast radius for closing DV-444. One document, one field. |

## Execution progression

1. **QA verification** — patch `app_name` in `aldcdevcsdb3c01` → reload `http://localhost:3000` as a user with access to the Navira app → confirm sidebar now reads "SKU Profitability".
2. **Production** — repeat the same patch against the prod-tier cosmos account in a coordinated window. Pending prod cosmos credentials confirmation (see tracker *Blockers*).
3. **Verification** — GEP-side confirmation + a spot-check with one shared-customer account.

## Sharing propagation

Automatic. The `application_metadata` container is partitioned by `/account_id` and queries are scoped to the owner account's partition (`da8904db`). Downstream customers who have been granted `Application_View` via RBAC read the **same single document** — renaming `app_name` once updates what every viewer sees. Evidence: `core_api/api/applications/db.py:5-12` (all queries are partition-scoped; no per-user copies).
